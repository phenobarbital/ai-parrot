## Implementation Notes

### Pattern to Follow
Spec §9 "Module 7" blueprint.

### Key Constraints
- Resolution errors from CreateFormTool must surface the exact ValueError
  text to the retry prompt — the message names the owner field and bad
  reference, which is what the LLM needs to self-correct.
- ARRAY `item_template` uses `field_id="item"` in extractors — this collides
  per-form if naïvely counted; item_template fields are NESTED (own uid) and
  `walk_fields` visits them, so two ARRAYs both using "item" WILL trip the
  duplicate-field_id validator. Extractors must suffix item ids
  (`f"{parent.field_id}_item"`) — note this as an intentional behavior fix in
  the completion note.
- Do not alter YAML operator-fallback leniency (`ValueError → EQ`, :454-457) —
  only the field reference becomes strict.

### References in Codebase
- `tests/unit/extractors/test_extractor_roundtrip.py` — round-trip suite that must keep passing

## Context

Spec §2 "Type codegen" + §3 Module 3 (codegen part). The UI must consume
generated TS types, not hand-written ones, so drift between Python models
and UI code becomes a `tsc` failure. This implements the pattern specified
(but never built) in `sdd/proposals/dev-loop-session-state-hitl.brainstorm.md:497-509`.

---

## Scope

- Implement `scripts/generate_ts_types.py`:
  - Imports the UI-consumed response models — `AdminStatus`, `AgentCounts`,
    `DependencyHealth` (from `parrot.server.ui.status`, TASK-2524) and a
    `BotsListResponse` model describing `GET /api/v1/bots`' shape
    (`{"agents": [...], "total": N}`) — defining the latter in
    `parrot/server/ui/status.py` or a sibling `models.py` if the handler
    has no response model to import.
  - Emits one JSON Schema file per model via `model_json_schema()` into
    `packages/ai-parrot-server/ui/schemas/` (gitignored or committed —
    committed, so UI CI can run without Python).
  - Deterministic output (sorted keys) for diff-ability.
- Wire `pnpm generate` in `ui/package.json`: runs
  `json-schema-to-typescript` over `schemas/*.json` →
  `ui/src/lib/types/generated/*.ts` (with a DO-NOT-EDIT banner). `pnpm
  build` depends on generate output being present.
- Drift test (Python side): regenerating schemas produces no diff against
  the committed `ui/schemas/` (fails when models changed without re-running
  codegen).
- Generated TS committed to git (reviewable; UI CI needs no Python).

**NOT in scope**: consuming the types in pages (TASK-2529/2530), CI wiring
(TASK-2531).

## Implementation Notes

### Key Constraints
- The script runs inside the activated venv (`source .venv/bin/activate`);
  keep it dependency-free beyond pydantic + stdlib.
- Idempotent + deterministic: `json.dumps(..., indent=2, sort_keys=True)`.
- Generated `.ts` files carry a header:
  `// GENERATED by scripts/generate_ts_types.py — DO NOT EDIT`.
- `json-schema-to-typescript` options: `additionalProperties: false` off
  for the permissive agent item; `bannerComment` for the header.
- Pydantic v2 discriminated unions emit `oneOf` + `discriminator` → TS
  tagged unions (dev-loop brainstorm :497-509) — not needed for these flat
  models but do not preclude it in the script design.

### References in Codebase
- `sdd/proposals/dev-loop-session-state-hitl.brainstorm.md:497-509` — the
  decided pattern this implements.

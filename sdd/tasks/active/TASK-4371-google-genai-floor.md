## Context

Implements spec §3 **Module 3** (floor half). The two pins diverge — `>=2.23.0` in
`ai-parrot-client-google`, `>=2.18.1` in the `google` extra of `ai-parrot-embeddings` — and the
client package documents a policy (pyproject.toml:17-26): **only a version actually exercised is
declared as the floor**. This task fixes the number by measurement, not by choice: install →
introspect → declare.

**Drift since the spec was written** (re-verified at task time, 2026-10-15): the spec says "the
current resolution is 2.24.0". After merging `origin/dev`, `uv.lock` resolves **2.28.0**
(`uv.lock:6482-6483`) while the shared venv still has **2.24.0** installed. The procedure below
uses 2.28.0 as the fallback, not 2.24.0, because the lock is what CI installs.

## Scope

1. In a **task-local** environment (never the shared `.venv`), install the candidate
   `google-genai==2.31.0` and introspect the SDK surfaces the Google client uses.
2. If every check passes, declare `>=2.31.0` in both pyprojects; otherwise fall back to the lock's
   `2.28.0` after running the same checks against it.
3. Extend the rationale comment in `ai-parrot-client-google/pyproject.toml` with date, version
   and what was introspected (same style as the FEAT-564 paragraph).
4. `uv lock --upgrade-package google-genai` so the lock resolves the declared floor.
5. Run the three Google test modules (against the shared venv's installed SDK — see Notes).

**NOT in scope**:
- `uv sync` / `uv pip install` into the shared `.venv` — forbidden from a worktree
  (`.claude/rules/worktree-management.md` §4). Syncing is the main-checkout operator's step after merge.
- Declaring `google-cloud-aiplatform` anywhere — the `<=3.1.0` storage caveat in
  `ai-parrot-embeddings/pyproject.toml:47-54` is about aiplatform and must stay intact.
- `docs/migration/video-reel-omni-veo-reliability.md` "Tested SDK versions" — referenced by the
  comment but not updated here.
- Any code change.

## Implementation Blueprint

### Steps (in order)
1. Run the introspection in a task-local venv — because the shared `.venv` is read-only from a worktree.
   Do it in **one** Bash call (the sandbox's `/tmp` is private per call):
   ```bash
   D=$(mktemp -d) && uv venv -q "$D/v" && uv pip install -q --python "$D/v/bin/python" "google-genai==2.31.0" \
   && "$D/v/bin/python" -I - <<'PY'
   import google.genai as g
   from google import genai
   from google.genai import types, errors
   print("version", g.__version__)
   assert "thinking_level" in types.ThinkingConfig.model_fields and "thinking_budget" in types.ThinkingConfig.model_fields
   for name in ("ComputerUse", "GenerateContentConfig", "CreateCachedContentConfig", "HttpRetryOptions", "HttpOptions"):
       assert hasattr(types, name), name
   c = genai.Client(api_key="x")
   for path in ("aio.models.generate_videos", "aio.operations.get", "aio.files.download",
                "aio.interactions.create", "aio.live.music.connect", "aio.caches.create", "aio.aclose"):
       obj = c
       for part in path.split("."):
           obj = getattr(obj, part)
   print("ALL OK")
   PY
   ```
   If it does not print `ALL OK`, repeat with `2.28.0` and use that version below.
2. Edit both pyprojects — because the floor must equal what step 1 exercised.
3. `uv lock --upgrade-package google-genai` (no sync) — because the lock must resolve ≥ the floor.
4. Run the Validation Commands.

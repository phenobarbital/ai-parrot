## Context

Implements spec §2 P3 (AC4–AC8). Sandbox cherry-picks require `extensions.worktreeConfig=true` and
exactly one effective `remote.origin.pushurl=no_push` on the target worktree, but only a manual

## Implementation Notes

- Common-config reads use `git -C <wt> config --file <common-dir>/config --get-all <key>` where
  `<common-dir>` = `git -C <wt> rev-parse --git-common-dir` (resolve relative to `wt`), so values
  from `config.worktree` are not mistaken for common ones.
- `enable` order: sandbox refusal → resolve → common-config refusals → `git -C <wt> config
  extensions.worktreeConfig true` → `git -C <wt> config --worktree --replace-all
  remote.origin.pushurl no_push` → verify `push_protection_ok`.
- `disable`: if `extensions.worktreeConfig` is not true, nothing worktree-local can exist → success.
  Else `config --worktree --unset-all remote.origin.pushurl`; exit 5 ("no such key") = success.
- CLI: `push-protection {enable,disable,status} target [--json]`; JSON body
  `{"worktree", "action", "protected", "exit_code", "message"}`.
- Launcher: wrap `enable` in `try/except (SyncError, OSError, subprocess.SubprocessError)`; print
  `push protection: enabled` or `push protection skipped: <reason>` to stderr. Import lazily (same
  reason as `stale_base_summary`). Run it regardless of `no_upstream`.

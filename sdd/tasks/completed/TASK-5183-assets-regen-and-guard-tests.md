## Implementation Notes

### Key Constraints
- Guard test scope (spec §3 M5): every `.md`/`.toml`/`.sh` under `.claude/`, `.agent/`, `.agents/`,
  `packages/ai-parrot/src/parrot/sdd/_assets/`, plus `CLAUDE.md`. A line naming `.claude/worktrees` is allowed
  only when it also contains `git worktree repair`. Skip `.claude/settings.local.json`, any path with a
  `worktrees` part (live checkouts, as the sibling test does) and `.claude/hooks/dangerous-actions-blocker.sh`'s two regex lines
  — easiest: also allow lines containing `(claude|parrot)` (the two-root regex form from TASK-5178).
- Twins test: for `/sdd-done` (`.claude/commands/sdd-done.md`, `.agent/workflows/sdd-done.md`, `.agents/skills/sdd-done/SKILL.md`),
  `/sdd-next`, `/remove-worktree` and the worker/planner/research/autopilot twins assert the text contains
  `parrot sdd worktree root --root`. Then EXECUTE the `MAIN_ROOT=…`/`WORKTREES_DIR=…` lines extracted from the
  Claude `sdd-done.md` in a temp repo with `bash -c`, under (a) no override, (b) relative `WORKTREE_BASE_PATH="wt dir/x"`,
  (c) absolute override with a space; assert `$WORKTREES_DIR/feat-FEAT-1-x` equals the path
  `parrot sdd worktree ensure --dry-run --json` reports for the same repo (or `plan_worktree` joined to the repo root).
- The wheel-only test runs `parrot sdd install` in its foreign repo (lines 569, 635, 662, 678, 709). After TASK-5179,
  `packages/ai-parrot/src/parrot/sdd/installer.py` refuses while a worktree is registered under `.claude/worktrees/`, so
  `_seed_worktree` (line 157) MUST create the worktree under the resolved root or every install step exits 1.
- The wheel-only test runs shipped snippets in a foreign repo: they now call `parrot sdd worktree root`, which the wheel
  ships (TASK-5175) — make sure the fixture's `parrot` resolves to the wheel's entry point.
- `parrot.sdd.audit` (TASK-5178) now reports `.parrot/worktrees/` lines in shipped assets as `monorepo-path`. These findings
  are advisory (no test gates them); list the count in the Completion Note.

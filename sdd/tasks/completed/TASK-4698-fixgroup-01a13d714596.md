## Context

`packages/ai-parrot-server/ui` depends on `dompurify ^3.4.16`, pinned to
`3.4.16` in `pnpm-lock.yaml`. GHSA-cg2g-xh64-v4q7 (critical, CVSSv4 9.2,
Dependabot alert #237) affects every `dompurify` release `>=3.4.4,<=3.4.16`.
The fix ships in `dompurify@3.4.17`, confirmed published on the npm registry.
This task implements spec §3 Module 1 in full: bump the version range,
regenerate the lockfile, and confirm the UI test suite still passes.

## Scope

- Change `"dompurify": "^3.4.16"` to `"dompurify": "^3.4.17"` in
  `packages/ai-parrot-server/ui/package.json`.
- Run `pnpm install` inside `packages/ai-parrot-server/ui` to regenerate the
  `dompurify` entries in `pnpm-lock.yaml` (importer block + top-level
  `packages:` entry, including the new `resolution.integrity`).
- Run the existing `vitest` suite and confirm it passes unchanged.

**NOT in scope**: adopting `SAFE_FOR_TEMPLATES`/`RETURN_DOM`/`IN_PLACE`
anywhere, any other Dependabot alert, any change to `markdown.ts`.

## Implementation Blueprint

> Pure dependency-version edit; no business logic. No `FILL IN` markers are
> needed — the whole change is mechanical.

### Steps (in order)
1. Edit `package.json`'s `dompurify` range — *why*: moves the declared
   range past the vulnerable ceiling so a fresh install can never resolve
   back to `3.4.16`.
2. Run `pnpm install` inside `packages/ai-parrot-server/ui` — *why*:
   regenerates `pnpm-lock.yaml`'s resolved version and integrity hash to
   match the new range.
3. Run `pnpm vitest run` — *why*: confirms no behavior regression from the
   patch bump.

### `packages/ai-parrot-server/ui/package.json` (MODIFY)
```json
# occurrences: 1 (verified: grep -c '"dompurify": "\^3.4.16"' packages/ai-parrot-server/ui/package.json)
# REPLACE line 39:
-    "dompurify": "^3.4.16",
+    "dompurify": "^3.4.17",
```
**Why this shape**: moves the declared range's floor past the vulnerable
ceiling (`<=3.4.16`) so `pnpm install` resolves to the patched `3.4.17`.

### `packages/ai-parrot-server/ui/pnpm-lock.yaml` (MODIFY)
Not hand-edited. After the `package.json` change, run:
```bash
cd packages/ai-parrot-server/ui
pnpm install
```
This regenerates the `dompurify@3.4.16` importer and `packages:` entries
(lines ~1312-1313 and ~3284-3286 as of this writing) to `dompurify@3.4.17`
(or later) with a fresh `resolution.integrity` hash.
**Why**: the lockfile is a derived artifact; `pnpm install` is the only
correct way to update it.

# TASK-2338: The shared catalog fixture, and the ratchet that reads it

**Feature**: FEAT-448 — field-type-catalog-reconciliation
**Spec**: `sdd/specs/field-type-catalog-reconciliation.spec.md` §5.5, AC7
**Status**: pending · **Priority**: high · **Effort**: M
**Depends-on**: TASK-2332, TASK-2335, TASK-2336

## Context

This is the deliverable that stops the feature recurring. Everything else in
FEAT-448 is paying off one instance of a divergence that went unnoticed for
three months because nothing compared the two catalogs.

The failure mode to design against is specific: a ratchet that compares our
enum to a SECOND list we also maintain is just the third list that drifts. The
client half (navigator-svelte FEAT-515 AC7) must be able to read the truth from
here rather than from a copy.

## Scope

- Publish the catalog as data, not only as a Python enum — the natural home is
  the existing `GET /api/v1/form-controls` response, which the client already
  consumes to build its palette. Adding the value-shape contract per type makes
  it the single source both sides can assert against.
- A test here asserting the served catalog matches `FieldType` exactly, in both
  directions.
- Record for the client half how to fetch it in CI without a running server (a
  committed snapshot regenerated by a script is acceptable; a hand-maintained
  copy is not — the difference is that the snapshot has a generator and fails
  when stale).

## Acceptance Criteria

- AC1 A test fails if a `FieldType` value is missing from the served catalog.
- AC2 A test fails if the served catalog names a type not in `FieldType`.
- AC3 The client half can obtain the catalog without hand-copying it, and the
  mechanism is documented in this task's completion note.
- AC4 The snapshot, if one is used, has a regeneration command and a test that
  fails when it is stale.

### Completion Note

**Investigation first.** `GET /api/v1/form-controls` (`controls/builtin.py`
seeding `controls/registry.py`) already registered one entry per `FieldType`
unconditionally (`for field_type in FieldType: meta = _BUILTIN_METADATA[field_type]`
— a plain dict lookup with no `.get()` default, so it already raises at
import time if any type is missing `_BUILTIN_METADATA`). TASK-2332/2335 had
already filled in every one of the twelve types there. So AC1/AC2
("a test fails if a FieldType is missing from / the catalog names a type
not in FieldType") were **already satisfied** before this task, by two
pre-existing tests:
- `tests/unit/test_controls_registry.py::test_builtin_seeds_every_field_type`
  (registry-level, runs fine in this environment).
- `tests/integration/test_form_controls_contract.py::test_endpoint_covers_every_field_type`
  (HTTP-level; asserts the same bidirectional set equality over the live
  endpoint's response).

What was genuinely missing, and what this task actually delivers:

**1. The value-shape contract per type (spec's actual ask).** Every
control's `snippet` field is a full FormField *creation example*
(`{"field_id": ..., "label": ..., "required": ...}`), not a value-shape
contract a client can validate a submitted value against — and it was
empty (`{}`) for 13 types including all twelve of this feature's, since
`get_form_field_schema_snippets()` was never extended for them (a
pre-existing, separate gap — see "Noted, not fixed" below). Added a NEW
`value_shape: dict[str, Any] = {}` field to `FieldControlMetadata`
(`controls/registry.py`), populated in `controls/builtin.py._seed()` via a
NEW public function `renderers/jsonschema.type_level_value_shape(field_type)`.

To avoid becoming "the third list that drifts" (this task's own stated
failure mode), `type_level_value_shape()` does NOT hand-maintain its own
per-type shape data — it reads `JsonSchemaRenderer`'s existing `_TYPE_MAP`
/ `_FORMAT_MAP`, plus a NEW shared `_STRUCTURAL_EXTRAS` dict that I
extracted from `_field_to_property()`'s previously-inline
`if ft == X: prop["items"/"properties"] = ...` blocks (TAGS, AVAILABILITY,
TRANSFER_LIST, plus TASK-2337's TREE_SELECT/MULTI_UPLOAD/CREDIT_CARD/PLACE
additions). Both the per-field renderer and the type-level catalog function
now read the SAME dict — verified with
`test_value_shape_matches_jsonschema_renderer` (parametrised over all
twelve types), which asserts `catalog.value_shape == type_level_value_shape(ft)`
exactly.

**2. The CI-without-a-server mechanism (AC3/AC4).** New script
`scripts/generate_form_controls_snapshot.py`:
- `python scripts/generate_form_controls_snapshot.py` — regenerates the
  committed snapshot `tests/fixtures/form_controls_snapshot.json` (a
  deterministic, type-sorted JSON dump of the full `get_controls()`
  catalog).
- `python scripts/generate_form_controls_snapshot.py --check` — exits 1
  with a diagnostic if the committed file doesn't match the live catalog
  (for a CI step, no live aiohttp server needed).
- `tests/unit/test_controls_registry.py::test_form_controls_snapshot_is_fresh`
  wires the same check into pytest (loads the script via
  `importlib.util.spec_from_file_location`, mirroring the existing
  `tests/unit/test_migrations_form_uid.py` pattern for `scripts/`/`migrations/`
  being plain directories, not packages).
- `test_form_controls_snapshot_covers_every_field_type` re-asserts AC1/AC2
  directly against the snapshot file's contents — the "read the truth from
  here rather than from a copy" mechanism the client half (navigator-svelte
  FEAT-515 AC7) needs: **commit
  `tests/fixtures/form_controls_snapshot.json` is the artifact the client
  repo can vendor/read in its own CI without booting parrot-formdesigner's
  server; regenerate+recommit it here whenever the catalog changes.**

**3. New tests** (`tests/unit/test_controls_registry.py`):
`test_value_shape_present_for_every_field_type`,
`test_value_shape_matches_jsonschema_renderer` (parametrised ×12),
`test_credit_card_value_shape_excludes_cvv_and_number`,
`test_form_controls_snapshot_is_fresh`,
`test_form_controls_snapshot_covers_every_field_type`.

`FieldControlMetadata`'s exact key set ("Guards against accidental field
additions... without a contract bump") — added `value_shape` to its

bump that test exists to force.

## Context

Spec §3 Module 1. This is a **design/compatibility gate**, not a mechanical package install.
Every later task (TASK-5470 onward) consumes the evidence this task records in
`sdd/state/FEAT-875/layout-compatibility.md`: the exact package tuple, the real Layout
activation import, the OCR-disable API, the page-identity metadata, and native heading quality.

The spec is explicit that the candidate versions (pymupdf4llm 0.2.9 with pymupdf 1.27.1) are a
**research starting point, not verified pins**, and that automatic Layout activation arrived in
pymupdf4llm 1.27.2.1. That release family must be avoided.

## Scope

- In an **isolated** environment (never the shared `.venv`), install candidate tuples starting with
  pymupdf4llm 0.2.9 + pymupdf 1.27.1 + a matching `pymupdf-layout`, and record the following:
  - the exact resolved versions, wheel/platform availability, Python constraints, and license metadata;
  - the real activation import or API (the distribution name `pymupdf-layout` does not prove the
    module is named `pymupdf_layout`);
  - how to disable automatic OCR, and how to suppress image file writes;
  - which page-identity fields the page-chunk output exposes (needed for TASK-5470's
    dense-page validation);
  - whether activation still works when `parrot.knowledge.pageindex` (its `__init__`) is imported first;
  - native heading quality on generated chapter, subsection, bold, and enumerated fixtures, plus the arxiv fixture;
  - legacy `extract_markdown_per_page(..., hdr_info=LayoutHeaders(...))` behavior with Layout installed and with it absent.
- Write the findings to `sdd/state/FEAT-875/layout-compatibility.md`, with the smoke commands and their results.
- **Only after** a compatible tuple is found and the maintainer approves the dependency addition
  (spec §8 open question), add a `bookstore-layout` extra to `packages/ai-parrot/pyproject.toml`
  that includes the existing bookstore requirements plus the verified Layout tuple. Reconcile the
  `agents` extra pins (`pymupdf==1.27.1`, `pymupdf4llm==0.0.27`, `pdf4llm==0.0.27`) so the
  workspace still resolves, then regenerate `uv.lock` with uv.
- Put test logs under `artifacts/logs/`.

**Stop condition:** if no compatible pre-automatic-Layout family passes the existing legacy suites
and resolves in the workspace, **stop**. Mark the task `done-with-issues` with the evidence; do not
expand scope or upgrade core PyMuPDF to make it fit (spec §3 M1, "revise this draft").

**NOT in scope**: any Python code under `parrot/` (that starts in TASK-5470), making Layout the
default, a general PyMuPDF 2.x migration, or committing environments or PDF copies.

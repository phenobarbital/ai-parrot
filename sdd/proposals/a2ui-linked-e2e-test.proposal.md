## 0. Origin

The full request is in `sdd/state/FEAT-610/source.md`. Condensed:

> FEAT-598 (A2UI Linked Surfaces) has landed on dev. The goal is to build a self-contained end-to-end example that uses nothing outside ai-parrot. From the query-slug `polestar_graduates_directory`, it builds an A2UI dashboard surface with:
> - KPI hero cards:
>   - total rows (17572);
>   - Pilates Studio graduates;
>   - Pilates Mat graduates;
>   - multi-graduates, meaning `len(graduation_details) > 1`.
> - Bar charts: graduates by country and by licensee.
> - A pie chart: count by `graduation_details.course`.
> - A filterable grid over all ~17k records.
>
> The renderer is HTML5, using echarts for charts and grid.js for the grid. Every widget has a "refresh" button that calls the query-slug API directly, with no AI involved (deterministic mode). The code is a client/server pair, `examples/a2ui/{server,client}.py`:
> - The server is a parrot/aiohttp app. It mounts QuerySource and the AuthHandler, serves the surface generated by an agent, and optionally exposes the agent itself.
> - The client handles login, stores the bearer token in localStorage, consumes the surface URL, renders it, and refreshes its widgets.

- Verbs: "crear", "renderizar", "refrescar". This is an enrichment/feature request, not a bug.
- Named entities: FEAT-598, `polestar_graduates_directory`, echarts, grid.js, QuerySource, AuthHandler, ai-parrot-server.
- Acceptance criteria provided: implicit. The request gives 4 KPIs, 3 charts, 1 grid, a per-widget refresh, and a login flow.

## 1. Synthesis Summary

FEAT-598 defines a linked surface as an A2UI **v1.0** `createSurface`. Its per-source `LinkedDataSource` descriptors live under `metadata.extensions.parrot_data_sources`, and components bind to them by JSON-pointer path only. Only `KPICard`, `Chart` and `DataTable` can be linked (F001–F003, F030–F031).

What the contract already supports:
- Agent-side, `QuerysourceToolkit.build_linked_surface` exists, but it builds only **one** component per call (F004, F018).
- Deterministic refresh exists in two lanes: the browser can POST to `/api/v3/queries/{slug}`, and the server can call `execute_sources` in-process (F005, F006, F011).

What is missing for a working demo:
- No helper composes a multi-widget dashboard.
- There is no per-widget refresh.
- No renderer uses echarts together with grid.js.
- No test covers a KPI + pie + grid dashboard.
- Two data prerequisites are unmet:
  - The JSONB `@>` filter needs querysource ≥5.1, but the shared venv has 5.0.0 (F013).
  - The course pie cannot be computed against the base slug, so it needs a second slug (F014).

The recommendation is to build the example as specified, plus four small changes in core, which the user approved in §5:
1. a multi-widget dashboard helper;
2. the querysource pin;
3. the pie-slice fix and the wire-doc fix;
4. per-widget refresh in the TS lane.

### 2.2 Constraints Discovered

- **Only tools may emit descriptors.** Any surface carrying `parrot_data_sources` must come from TOOL output. An LLM-authored one fails with `DATA_SOURCES_NOT_ALLOWED_FOR_LLM` (`catalog/base.py:89`). *Implication*: the agent must call a tool that composes the dashboard; it cannot write the JSON itself. *Evidence*: F001
- **Components hold no query.** Widgets bind only `{"path": "/<key>/rows"}`, and the query lives in the source descriptor. *Implication*: a per-widget refresh button has to map component → bound source key → descriptor. *Evidence*: F002, F003
- **Row caps.** Snapshots hold at most 500 rows and a client fetch at most 5000. *Implication*: the ~17.5k-row grid must page on the server (`_limit`/`_offset` plus a `count(*)` call); grid.js `server` mode fits this. *Evidence*: F005, F012, F037
- **Payload semantics.** `fields` goes into the SQL verbatim, so aggregates and aliases work, but only if the slug's SQL is `SELECT *` or uses `{fields}`. `filter`, `group_by`, `ordering`, `_limit` and `_offset` are all supported. `paged`/`page` are parsed but ignored. *Evidence*: F012
- **JSONB `@>` needs querysource ≥5.1.0.** The shared venv has 5.0.0, and core `ai-parrot[db]` pins `>=4.1.11` while `ai-parrot-tools[db]` pins `>=5.1.1`. *Evidence*: F013
- **Multi-graduates KPI.** It can be expressed in `fields` as `count(*) FILTER (WHERE jsonb_array_length(graduation_details) > 1) AS multi_graduates`. *Evidence*: F014
- **Course pie.** It cannot be computed against the base slug: set-returning functions are not allowed in GROUP BY, and the payload cannot change FROM. It needs a second slug (with LATERAL `jsonb_array_elements`) or a multi-query `tExplode` pipeline. *Evidence*: F014
- **Slugs live in the database.** They are rows in `<schema>.queries`; there is no file-based loading. *Implication*: the second slug is seed data written to a shared DB, and the example needs an idempotent seed step. *Evidence*: F016
- **Infrastructure.** Importing QuerySource requires `DBUSER`. Slug execution opens Redis. AuthHandler sessions need Redis. BasicAuth needs the authdb Postgres. *Implication*: "no external dependencies" means no code outside the workspace; Postgres and Redis from `env/.env` are required. *Evidence*: F017, F021, F027
- **PBAC.** `QS_PBAC_ENABLED=true` in `env/.env`, so a request with no session or no matching policy gets a 404. *Implication*: the demo user needs `slug:execute` on both slugs, or the example documents the policy it needs. *Evidence*: F015
- **Gitignore.** `examples/**/*.py` (`.gitignore:20`) and `examples/**/*.html` (`.gitignore:37`) both match `examples/a2ui/`. *Implication*: a whitelist entry is needed, otherwise the files are silently never committed. *Evidence*: F026
- **Wire-doc drift.** The wire doc §3 says the route is only `/api/v1/{tenant}/...` with `querylimit: 500`. The code uses `/api/v3/...` when no tenant is set, capped at 5000. *Evidence*: F007
- **Degrade, don't throw.** Renderers draw Parrot components natively, break anything else down into Basic primitives, and show a visible notice for an unknown component instead of throwing (`degrade.py:46`). ECharts options never travel on the wire. *Evidence*: F039

## 3. Probable Scope

### What's New

- **`examples/a2ui/server.py`**: an aiohttp app. It mounts:
  - `QuerySource(lazy=False).setup(app)`;
  - `AuthHandler(backends=[BasicAuth])` (existing authdb users);
  - optionally, `BotManager(enable_database_bots=False, enable_registry_bots=False)` with the demo agent.

  It serves the static renderer at `/` and the surface at its own route (e.g. `GET /api/a2ui/dashboard`). That route runs the agent, whose TOOL output is the linked surface, and caches the envelope. An idempotent seed step upserts the `polestar_graduates_by_course` slug. The mount order follows `app.py`.
- **`examples/a2ui/client.py`**: a thin launcher that opens the served page (`--open`). The actual client is a static HTML5 page (`examples/a2ui/static/`: `index.html`, `renderer.js`) that does the following:
  - logs in via `/api/v1/login` with `X-Auth-Method: BasicAuth` and stores the JWT in localStorage;
  - fetches the surface and walks the v1.0 component tree;
  - renders KPICard as hero cards, Chart (bar or pie) with echarts, and DataTable with grid.js in `server` mode (paging and search mapped to `_limit`/`_offset`/`filter`);
  - adds a **refresh button per widget** that re-POSTs that widget's descriptor `conditions` to `/api/v3/queries/{slug}` with the bearer token.
- **Multi-widget dashboard tool/helper** (e.g. `QuerysourceToolkit.build_linked_dashboard`, or a builder over `builders.build_linked_surface`). It takes N widget specs (kind, slug, conditions, binding) and returns one TOOL-origin linked `createSurface`, so the agent emits the whole dashboard in a single tool call.
- **Widget → query map** (the example's agent prompt / tool input):

  | Widget | Slug | Conditions |
  |---|---|---|
  | KPI total | base | `{"fields": ["count(*) as total"]}` |
  | KPI Pilates Studio | base | `{"fields": ["count(*) as total"], "filter": {"graduation_details": {"@>": [{"course": "Pilates Studio"}]}}}` |
  | KPI Pilates Mat | base | same, with `"Pilates Mat"` |
  | KPI multi-graduates | base | `{"fields": ["count(*) FILTER (WHERE jsonb_array_length(graduation_details) > 1) AS multi_graduates"]}` |
  | Bar by country | base | `{"fields": ["country", "count(*) as graduates"], "group_by": ["country"]}` |
  | Bar by licensee | base | `{"fields": ["licensee", "count(*) as graduates"], "group_by": ["licensee"]}` |
  | Pie by course | `polestar_graduates_by_course` (new, seeded) | `{"fields": ["course", "count(*) as graduates"], "group_by": ["course"]}` |
  | Grid | base | paged `_limit`/`_offset` plus a `count(*)` total; `filter` taken from the grid search box |

- **Tests.** A fixture/golden with KPI + pie + grid. Server tests with fake QuerySource/authdb, following the `test_linked_surfaces_e2e.py` pattern. A documented manual E2E run against the real slug.

### What Changes

- **`packages/ai-parrot/pyproject.toml`**: `querysource>=4.1.11` → `>=5.1.1` in the `db` extras (l.225, 688). This is needed for JSONB `@>`. *Evidence*: F013
- **`packages/ai-parrot-visualizations/src/parrot/outputs/a2ui_renderers/echarts.py`::`_build_option`**: pie/donut series get `{name, value}` slices. *Evidence*: F034
- **Wire doc §3** (FEAT-598 docs, TASK-3796): fix the route (v3 when no tenant, v1 when a tenant is set) and the `querylimit` cap (5000). *Evidence*: F007
- **`packages/ai-parrot-server/ui/src/lib/components/agents/canvas/a2ui/linked/index.ts`::`LinkedLane`**: export a per-source refresh (`refreshSource(key)` over `runSource`) and wire an optional refresh affordance in `A2UISurface.svelte`. *Evidence*: F006, F036
- **`.gitignore`**: whitelist `examples/a2ui/**` (`.py`, `.html`, `.js`). *Evidence*: F026

### What's Untouched (Non-Goals)

- The server-lane `/api/v1/ui/surfaces/{id}/refresh` and the persisted `PgUISurfaceStore`. The example serves its own surface route, per U3.
- The FEAT-598 descriptor schema (`LinkedDataSource`). The example only consumes it.
- New A2UI catalog components (a Grid container, a refresh prop). Refresh is a renderer affordance, not wire data.
- A demo auth backend or NoAuth. BasicAuth against the existing authdb is used, per U2.
- Fixing `transform.ref` in the Python executor, or the `ensure_snapshot` owner re-check (F008). Log these in the ledger if they are still relevant.

### Patterns to Follow

- The mount order and `QuerySource(lazy=False).setup(app)` from `app.py`. *Evidence*: F010, F027
- The plain-aiohttp example layout with `static/index.html` and `add_static` from `examples/clients/voice/server.py` and `examples/forms/form_server.py`. *Evidence*: F024, F025
- The login and localStorage token pattern from `admin_login_page`. *Evidence*: F022
- The fetch contract (`queryUrl`, `querylimit` cap, 404 → `SourceUnavailable`, frame selection) from `linked/fetch.ts`. Port it to vanilla JS rather than inventing a new one. *Evidence*: F006, F036
- The vendored `formats/assets/echarts.min.js`, or echarts@5.4.3 with real SRI (`tools/interactive/catalog/libraries/echarts.md`). grid.js@6.2.0 needs real SRI hashes; the catalog entry has placeholders. *Evidence*: F035
- Degrade, don't throw, on unknown components. *Evidence*: F039

### Integration Risks

- **querysource version.** The shared venv has 5.0.0, so the `@>` KPIs fail until it is upgraded. Upgrading a shared venv is an operator action; it must not be done from a worktree. *Mitigation*: raise the pin, and document the requirement in the example README. *Evidence*: F013
- **The slug is unverified.** Where `polestar_graduates_directory` is defined (`public.queries` or a tenant), its SQL (`SELECT *`/`{fields}`), and the 17572 count were not checked; a read-only DB lookup was denied during research. If the SQL does not allow `fields`, aggregates are ignored. *Mitigation*: the first spec task verifies the slug and records its definition. *Evidence*: F016
- **v3 single-slug semantics.** The TS lane POSTs plain conditions to the multi-query handler (`/api/v3/queries/{slug}`), which treats the body as that slug's conditions (`../querysource/querysource/handlers/multi.py` `query`). Medium confidence: the FEAT-598 E2E test fakes QuerySource. *Mitigation*: the spec includes a live check of `fields`/`filter`/`group_by` through v3, with a fallback to `/api/v2/services/queries/{slug}`. *Evidence*: F006, F011
- **PBAC denials.** QS PBAC returns 404 with no session or no matching policy, and the demo user needs `slug:execute` on both slugs. Also verify that the QS guardian and parrot `setup_pbac` coexist on `app['security']`. *Evidence*: F015
- **Svelte change untested.** The Svelte lane was never run through vitest/svelte-check (F008). The per-widget refresh change should come with real vitest runs. *Evidence*: F008

# F003 — FlowContext shared_data is a plain dict, no versioning, no ACL

## Summary

**[FC-004] FlowContext shared_data is a plain dict, no versioning, no ACL** — `bots/flows/core/` contains `context.py`, `fsm.py`, `node.py`, `result.py`, `transition.py`, `types.py` (Q024 tree). `FlowContext` (dataclass, 365 lines) is the per-run state tracker shared by AgentCrew and AgentsFlow: `results`/`responses`/`node_metadata` keyed by node_id, completion sets, `errors`, and `shared_data: Dict[str, Any]` — an arbitrary key-value dict with no writer ownership, no version, no subscriptions and no ACL. It binds an optional `agent_registry` (resolve_agent by name via `get_bot_instance`) and a `trace_context` (W3C TraceContext, FEAT-176) and can snapshot itself for checkpointing (FEAT-399).

**[FC-017] trace_id lives in observability recorders and FlowContext; TraceContext class not in parrot src** — `trace_id|correlation_id|traceparent` over observability, bots, tools: `observability/recorders/{models(3),subscriber(4),openlit_recorder(2),prometheus_recorder(1),logging_recorder(1)}.py`, `observability/subscribers/trace.py` (1), `tools/executors/abstract.py` (1). `FlowContext.trace_context` carries a W3C `TraceContext` (FC-004) imported from `parrot.core.events.lifecycle`, but `grep 'class TraceContext'` over `packages/ai-parrot/src/parrot` finds **no definition** — it is re-exported from a dependency (likely navigator-eventbus/navigator-observability). Matrix tunnels use their own `correlation_id` futures (FC-008). An integration test `tests/integration/events/test_a2a_trace_propagation.py` already asserts trace propagation across an A2A hop.

**[FW-011] FlowContext.shared_data is a plain dict shared by all nodes (no single-writer, no versioning, no ACL, no subscriptions); checkpointable via to_snapshot** — `bots/flows/core/context.py::FlowContext` (l.56, dataclass) is the shared execution state for AgentCrew and AgentsFlow: `shared_data: Dict[str, Any]` (l.94, 'Arbitrary key-value data shared across all nodes (replaces AgentContext.shared_data)'), `agent_registry: Optional[AgentRegistry]` (l.97) used by `resolve_agent(agent_ref)` → `agent_registry.get_bot_instance` (l.154), `trace_context: Optional[TraceContext]` (l.112), `completed_tasks`, `node_metadata`, `mark_completed` (l.177), `mark_failed`, `get_input_for_node` (l.259), `to_snapshot()` → `ContextSnapshot` (checkpointing; excludes registry/synthesis_client/trace_context). Added in TASK-976 together with `NodeResult`. This is a mutable dict with no writer ownership, no version/compare-and-set, no ACL per key and no change notifications — the brainstorm's VERIFY 'no shared versioned key-value with ACLs' is CONFIRMED. A free wiki query for 'blackboard single writer versioned' returned only unrelated versioned stores (`skills/store.py::SkillRegistry`, `tools/execution_plan/models.py::PlanRunMetadata` — 'versioned plan_run document persisted in the checkpoint shared-data projection', which shows shared_data already hosts one versioned document by convention).

**[FW-013] TraceContext (FEAT-176 / TASK-1182) exists in parrot.core.events.lifecycle and already propagates through A2A tool execution; FlowContext carries it** — `TraceContext` is a dataclass in `parrot.core.events.lifecycle` (TASK-1182, FEAT-176; moved by TASK-1820 'Move core lifecycle machinery (base, trace, meta)'), documented in `packages/ai-parrot/docs/lifecycle_events.md`. An integration test `tests/integration/events/test_a2a_trace_propagation.py` ('A2A trace context propagation through tool execution') shows the trace already crosses an agent→remote-agent hop. `FlowContext.trace_context` (FW-011, l.112) carries it through crew/flow runs. So the parent brainstorm's 'shared `trace_id` generated by the caller and propagated' has an existing carrier; the gap is only the cross-network propagation (gRPC metadata/bus headers) and the per-performative audit join.

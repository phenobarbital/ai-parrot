# F019 — images/media/files are List[Path] (URL-mangling) and parse_response drops non-existent paths

## Summary
`AIMessage` declares `images`, `media` and `files` as `Optional[List[Path]]`, `documents` as `Optional[List[Any]]`, and `data`/`structured_output` as `Optional[Any]`. Pydantic coerces a `str` to `PosixPath`, and pathlib collapses `//`. I checked this in the venv: `'https://cdn.x.com/fig/1.png'` becomes `'https:/cdn.x.com/fig/1.png'`. `AgentResponse` repeats the same `List[Path]` typing with `validate_assignment=True`, and its `files` field is `List[str]`. `parse_response` adds an entry from images, media or files only when `path.exists()` is true, so remote URLs are silently dropped. The single pass-through is a `str` beginning with `data:` in `documents`.

## Notes
- WRONG in the brainstorm: setting `AIMessage.images=[presigned_url]` does not deliver figures. The Path coercion mangles the URL, and `parse_response` drops it because `exists()` is False.
- Workable routes:
  - (a) Download figures to a local temp file and put that Path in `images`. This works for Telegram and WhatsApp; Teams and Slack only show a caption.
  - (b) Change `parse_response` and the `ParsedResponse` typing to keep `http(s)` strings.
  - (c) Put `data:image/...` base64 strings in `documents`. Only Teams renders these.
  - (d) Reuse `ChartData.public_url`. WhatsApp already honours it.
- Other `images` bookkeeping in parser.py L375-389 (chart detection) also assumes Paths.

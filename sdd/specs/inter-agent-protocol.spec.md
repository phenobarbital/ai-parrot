## 1. Motivation & Business Requirements

### Problem Statement

Agent-to-agent traffic across a trust boundary is paying for two things it does not need: human-readable wire formats and an LLM invocation on every hop. The cost unit that matters is tokens in the receiver's context, not bytes on the wire; A2A (JSON-RPC, agent cards, free-text tasks) and plain REST+JSON optimize neither.

Driving scenario: an ai-parrot agent inside an HR network has Workday and other HR systems as tools. By policy those tools are never exposed. An external ai-parrot agent on another network needs curated answers (headcount by department, manager of X, a dataframe or a C4 diagram) through a public endpoint. Today that means A2A or REST: JSON serialization on both ends, the raw payload landing in the external agent's context, and an LLM on the internal side interpreting every request.

Research confirmed the brainstorm's "does not exist yet" list: the only cross-network path today is A2A over JSON/aiohttp (`parrot/a2a/client.py`), which returns the remote artifact text straight into the caller's context, and the serving side (`A2AServer`) exposes the agent's *tools* as skills. The building blocks the protocol needs do exist as patterns: ToolManager's register/unregister and per-provider schema compile, WorkingMemoryToolkit's "the agent never sees raw frames" summaries and its immutable, checksummed task-memory blob store, the signed append-only `AuditLedger` signers, PBAC enforcement below the LLM, per-call usage records with ContextVar attribution, and a strict Arrow-IPC frame transport. Two brainstorm decisions rested on wrong premises and were corrected in the proposal: D10 (`AgentRegistry` does not register remote agents today) and D6 (Polars is declared nowhere; the repo is pandas + pyarrow).

What we want instead is a typed remote procedure between two ai-parrot agents that (1) degrades to deterministic RPC with zero tokens whenever the call matches a contract capability, (2) never puts raw data in any agent's context, (3) carries security and provenance as first-class fields, and (4) stays open enough that non-parrot agents can join through adapters. Its name is **Squawk** (Q13).

### Goals

- **G-A Receiver-token efficiency first, latency second.** A result that is an artifact costs the external LLM a descriptor (≈100–200 tokens, G1 bounds it at < 250 for a 10k-row frame), never the payload.
- **G-B Deterministic fast path.** A call that matches a contract capability with `backing: deterministic` runs the bound tool and returns typed data with no LLM invocation on the serving side.
- **G-C Raw data never enters an agent context.** Results travel as handle + descriptor + provenance; bytes go to a content-addressed blob store on the receiving network and cross the boundary exactly once.
- **G-D Security boundary as a design input.** The serving agent exposes capabilities, never its tools; policy (redaction by data class, aggregation minimum, row caps, per-caller rate limit, token budget) is enforced below any LLM, fails closed, and every decision is a signed ledger line.
- **G-E One envelope, two carriers.** The same Call/Result/Progress/Error messages run as point-to-point Cap'n Proto RPC and as navigator-eventbus traffic consumed by a subscriber (U4: both in v0).
- **G-F Open spec.** A non-parrot client can consume a contract directly over the wire, and A2A / MCP adapters sit at the edge (D14).
- **G-G Three-level telemetry.** Served ledger, received ledger and a shared cross-boundary trace (`trace_id` generated by the caller) join the two sides without either depending on the other's cooperation (D13).
- **G-H Promotion loop.** Served-ledger aggregation drives agent-proposed, human-approved promotion of recurring LLM-backed requests into deterministic capabilities (Q10).

### Non-Goals (explicitly out of scope)

- Human readability on the wire — humans read the audit log, whose renderer prints any stored envelope (D2).
- A new "agent dialect" (STE100-style or learned codes), latent-state or KV-cache exchange, free-form agent conversation, and replacing MCP or A2A inside ai-parrot (brainstorm non-goals).
- Roost (FEAT-747): performatives, interaction protocols, blackboard, local carriers. Roost reuses the envelope, handles, blob store, catalog and gate defined here; the placement of Roost's code relative to the new satellite is §8 Q3, decided in the FEAT-747 spec.
- The A2A JSON-RPC/REST surface, `AgentCard` discovery (FEAT-272), `A2AMeshDiscovery` and `A2AProxyRouter`: untouched, they remain the inbound `kind=a2a` path and the A2A adapter's target.
- MCP transports (stdio/http/streamable-http/sse/unix/websocket/quic), `MCPClient`, `MCPToolProxy`: untouched; the MCP adapter is additive.
- `parrot/clients/base.py` beyond consuming the existing `_apply_cache_hints` hook in G4.
- The existing `AuditLedger` / `AuditLedgerEntry` schema and the `CredentialBroker` gate: reused only through the `AbstractKMSSigner` contract.
- FEAT-704 semantic-layer tasks and the `ai-parrot-semantic` satellite: only the shared-contract decision (U1, refined by §8 Q1) touches them — TASK-4474/4476 are amended, outside this feature, to import `parrot.interagent` instead of defining their own handle/ledger models; nothing else of FEAT-704 changes here.
- navigator-eventbus and navigator-auth internals: outside this repo; §7 records what the feature needs from them (a `reply_to` request/reply convention and a bytes-safe serializer; Biscuit issuance and attenuation) and G5/G6 measure the gap.
- The conversation `ArtifactStore` (`parrot/storage/artifacts.py`) and the A2UI structured-artifact contract.
- A `parrot squawk` CLI. Promotion approval and ledger rendering are Python APIs with a documented procedure in v0.
- Polars as a frame engine (U3: pandas + Arrow IPC in v0; Polars is an optional engine for a later feature, D6 amended). `polars` is present in the venv only transitively and MUST NOT be imported.
- A gRPC transport, *unless* G2 fails: the proposal rejected the brainstorm's gRPC default in favour of Cap'n Proto (Q6); gRPC with opaque bytes is the documented fallback swap, not a parallel implementation.

## 2. Architectural Design

### Overview

Squawk is a contract-driven, binary, streaming RPC between two ai-parrot agents, shipped as a **new satellite distribution `ai-parrot-squawk`** (U5) contributing the `parrot.squawk` namespace, with core receiving (a) the neutral, transport-free protocol contract under `parrot/interagent/` — handles / descriptors / provenance / served-ledger entry / error codes (U1 + S5) plus the contract models, category hashing, the Pydantic message mirrors, the capability → `ToolDefinition` compiler and the JSON bus-payload serializer (§8 Q3, so FEAT-747 Roost never imports the satellite; core stays free of `pycapnp` and `biscuit-python`) — and (b) four seams: ToolManager category mount/unmount, a handle-only WorkingMemory route, remote-agent discovery fields on `AgentRegistry` / `BotConfig` (U2), and a capability-call telemetry record + lifecycle event (S11). The dead gRPC MCP stub (`grpc_session.py`, `mcp.proto`) and the reserved `grpc_*` fields of `MCPServerConfig` are deleted in the same feature (U5).

The **contract** is the only thing shared across the boundary: a versioned catalog of `SquawkCapability` entries grouped by `CapabilityCategory`, hashed per category (SHA-256 over the canonical Pydantic JSON — S4), exchanged once per version in the handshake and cached; afterwards calls carry only `cap_id`, `contract_hash` and canonical-JSON `args`. A call with a stale hash is refused with `STALE_CONTRACT` carrying the current category. Additive changes keep the major version; removals and type changes bump it and carry a deprecation window.

On the **serving side** a deterministic `CapabilityDispatcher` maps `cap_id` → bound tool (or an LLM-backed capability with typed input, structured output and a tool allowlist equal to the contract itself — D9). Dispatch order is fixed: handshake-established peer identity and Biscuit scope (M10, Q7) → contract-hash check → `CapabilityPolicyGate.pre_call` → budget check → **`ToolManager.execute_tool(..., permission_context=ctx)`** (never `tool._execute` — S7) → `gate.post_result` (redaction by data class via `ScrubPolicy` / `OutputScrubber`, aggregation minimum, row cap) → `ServedLedger.append(required=True)` (sign → durable commit → acknowledge — S8) → result. The gate is fail-closed: a missing `PermissionContext` or an unavailable policy engine is `POLICY_DENIED` / `UNAUTHORIZED`, never a pass. Per-caller limits and k-anonymity live inside the gate because the PBAC matcher is resource-only (F023).

On the **calling side** a `SquawkRemoteToolkit` (an `AbstractToolkit`) owns the always-mounted catalog tools (`catalog_list` / `catalog_mount` / `catalog_unmount` / `catalog_search` / `catalog_find`, D8). Mounting a category registers one `CapabilityTool` per capability in ToolManager through the new atomic `mount_category` seam (S3); the planner may pre-mount from intent with no LLM turn and the model may mount/unmount mid-conversation (Q11; G4 verifies prompt-cache behaviour). `CapabilityTool._execute` calls the remote, and routes the result by `returns`: an inline struct is returned as-is; an artifact is streamed as Arrow IPC batches (or opaque bytes) into the local `SquawkBlobStore`, verified against its sha256 key, and registered in WorkingMemory through the Python-only `register_handle` route as a `HandleEntry` whose summary is the descriptor and never the bytes (S6). Local affordance tools (`df_query`, `df_sample`, `df_join`, `df_describe`, `chart_from_df`, `df_to_text`) operate on handles with toolkit-enforced materialization caps and publish derived results as new handles, so derived data also stays out of context. Descriptors are session-only by default and durable when `task_memory` is configured (Q9).

**Handles** are owner-bound and never bearer tokens: `HandleStore.claim()` re-verifies owner (or an explicit grant) and expiry, and every mismatch raises the same `handle_unavailable` code — the semantics FEAT-704 TASK-4476 specifies (`semantic-layer.spec.md:634-671`), lifted into core now; FEAT-704's TASK-4474/4476 are amended to import them (U1 refined by §8 Q1). The **blob store** is a byte-object store with content-hash keys, ACL, TTL, dedup-by-digest and streaming writes, with a local-disk and a file-manager (object storage) backend chosen per deployment (Q8); the task-memory `ArtifactBlobStore` is the pattern it follows (publish-then-reference, verify after write, bounded reads), not its base class (S9). Handshakes advertise known digests so the server skips bytes the client already holds.

**Transport**: Cap'n Proto RPC (`pycapnp`) is the native carrier (Q6) — capabilities as first-class objects, promise pipelining, cancellation through a returned `Operation` capability, server streaming through a client-supplied `ProgressSink`. mTLS identifies the calling agent and its network; the Biscuit token travels in the `Hello` handshake message, never in the call payload. The message set (`squawk.capnp`) is transport-neutral by construction: the same structs are published on navigator-eventbus by the **bus carrier** (U4) with `reply_to`, `correlation_id` and dedup by `idempotency_key`. G2 (Cap'n Proto + Arrow IPC + cancellation + `PARTIAL`) and G6 (bus carrier) are hard v0 gates.

### Carrier semantics (the subset each carrier guarantees)

| Property | RPC carrier (Cap'n Proto) | Bus carrier (navigator-eventbus Streams) |
|---|---|---|
| Unary call | yes | request/reply over `reply_to`, async |
| Server streaming + `Progress` | yes (`ProgressSink`) | `Progress` messages published to `reply_to` |
| Cancellation | synchronous, reaches the running tool (`Operation.cancel`) | best-effort `Cancel` message; result may still arrive as `CANCELLED` or `PARTIAL` |
| Delivery | exactly the RPC's | at-least-once; consumer dedups by `idempotency_key`; undeliverable results go to the DLQ |
| Identity | mTLS peer + Biscuit in `Hello` | Biscuit in envelope metadata; peer identity from the bus principal |
| Payload | packed Cap'n Proto + binary frames | `BusPayloadSerializer` (core): the message's JSON with every `bytes` field base64-encoded, inside `EventEnvelope.payload`; a Squawk-owned convention that navigator-eventbus adopts later (§8 Q2) |
| Trace | `trace_id` in `Call` | `trace_id` + `correlation_id` on the `EventEnvelope` |

The bus carrier is never described as synchronous RPC (S1 nuance); it exists so that FEAT-747 and subscriber-style consumers use the same messages.

## 3. Module Breakdown

### Gate and Dependency Rules (Lane 0 — the FEAT-571 pattern)

G1–G6 are separate SDD gate tasks, initially unrun. Each commits a reproducible report under `sdd/state/FEAT-746/spikes/G<N>-<slug>/report.md` (commands, versions, data provenance, raw metrics, pass/fail, and a proposed amendment to this spec); logs go to `artifacts/logs/`. ## 7. Implementation Notes & Constraints

> Architecture decisions stay with the thinking model; a delegated implementation only expresses decisions recorded here and in the task blueprints.

### Patterns to Follow
- **Remote tools become local `AbstractTool`s** via a proxy registered in ToolManager (`MCPToolProxy`, `A2ARemoteSkillTool`); `CapabilityTool` keeps the shape and changes only the result route (F001, F011).
- **Own entry model + core signers + async storage callable, fail-closed when required** (FEAT-704 `SemanticAuditLedger` over `AbstractKMSSigner`); `AuditLedger.append`'s swallow-and-continue is explicitly NOT the pattern (S8).
- **Guardrail-first enforcement** in `execute_tool` with sanitized denial reports (`PBACToolCallGuardrail` / `PolicyDenialReport`); `POLICY_DENIED` carries a `detail` string of the same sanitized shape, never policy internals.
- **Publish-then-reference, checksum, bounded page reads, strict no-pickle Arrow IPC** (`ArtifactBlobStore`, `repl_worker/transport.py`) — copied as invariants into `SquawkBlobStore` and `frames.py`.
- **Per-agent mount with canonical PBAC resource names** (`AgentMCPMount` mirroring `A2AServer.setup()`) for the MCP adapter; the dispatcher's `permission_context_for` names resources `squawk:<agent>:cap:<cap_id>`.
- **Explicit version field, auth in the handshake, open dicts as JSON strings** (navigator-eventbus `parrot.events.v1`, formerly TASK-1791) — the capnp schema carries `protocolMajor`; `args`/`inline` are canonical JSON bytes.
- **"Mirror the invariant subset of a draft external spec; quarantine wire compatibility behind an adapter"** (FEAT-322) for the A2A/MCP adapters.
- **FEAT-391 lifecycle hooks** (`_open`/`_close`/`auto_open`) for every toolkit holding a connection; never redefine them for other purposes.
- **FEAT-710 dedicated `EventBus` instance** with outbox and `event_id` dedup for the bus carrier.
- Satellite packaging: copy `packages/ai-parrot-advisors/pyproject.toml` (`[tool.setuptools.packages.find] where = ["src"]`, `namespaces = true` at :45-47; `ai-parrot = { workspace = true }` at :53); never add `src/parrot/__init__.py`.
- Config through `parrot.conf`'s `config.get(key, fallback=...)`; secrets (Biscuit root key, blob encryption key) only from environment variables.
- Charts from `chart_from_df` return structured-chart/A2UI data; no matplotlib.

### Known Risks / Gotchas
- **Cap'n Proto RPC in Python (Q6/S2)** — `pycapnp` 2.2.4 is the only maintained binding; its asyncio RPC layer is younger than grpc.aio and has no precedent here. G2 is a hard gate; on failure M3/M4 swap to gRPC with opaque `bytes` fields in the same message set (grpcio 1.84 / protobuf 6.31 already in the venv via `navigator-eventbus[grpc]`). The schema MUST stay transport-neutral (no capnp-only semantics leak into `messages.py`).
- **FEAT-704 overlap (U1 refined by §8 Q1)** — M1 lifts the *spec'd* claim/ledger semantics (`semantic-layer.spec.md:605-671`) rather than waiting for TASK-4474/4476 (0/26 done, built branch salvage-only). The cost is an amendment to those two FEAT-704 tasks (import `parrot.interagent`; drop their private `ResultHandle` owner tuple / `SemanticAuditLedger` append contract) that must land before they are implemented — tracked outside this feature; this spec never touches `parrot.semantic`.
- **Core now carries protocol data models (§8 Q3)** — `parrot.interagent` must stay free of `pycapnp`, `biscuit-python`, `parrot.squawk` and `parrot.semantic` imports (AC22 tests it); the binary codec and every transport remain in the satellite. The price is that a wire-schema change touches core (`messages.py`) and the satellite (`squawk.capnp` + codec) together — one task owns both edits.
- **Bus carrier runs on a Squawk-owned convention (U4/G6, §8 Q2)** — navigator-eventbus 0.4.0 has no `reply_to` helper on Streams and JSON-only payloads, so M11 ships `BusPayloadSerializer` (JSON + base64 bytes, ~33% overhead on frames) and its own reply-topic layout; the upstream change request is filed by G6 and its adoption is a later transport swap inside M11, not a redesign.
- **Biscuit issuance lives in navigator-auth (Q7/G5, §8 Q4)** — none exists today; it is the user's deliverable in that package (root keypair, lifetime, attenuation endpoint). M10 verifies and attenuates locally so the serving side is complete; until navigator-auth ships, G5 and the test suite use a test-only issuer and no production tokens can be minted.
- **Fail-open precedents nearby (S7)** — `PBACToolCallGuardrail` passes without a context and `PBACPermissionResolver` passes without navigator-auth; `A2AServer._invoke_tool` is ungated. The dispatcher must never route around `execute_tool`, and the gate must treat a `None` context as denial; AC05 tests both.
- **Raw-data leak through generic WorkingMemory APIs (S6)** — `store_result` + `get_result(raw)` would reintroduce the leak; only `register_handle` lands remote results, and `_apply_raw_policy` skips `HANDLE` entries.
- **Discovery conflation (S10, accepted risk under U2)** — remote entries in `AgentRegistry` carry discovery fields only; `get_instance` refuses them; `A2AMeshDiscovery` keeps health/skills for A2A. A later read-through from the mesh is out of scope.
- **ToolManager category index was never maintained (S3)** — `mount_category` is the first writer; `clone()` copies `_categories`, so mounts survive cloning, and `unregister_tool` must now scan the index (O(categories), acceptable).
- **Prompt-cache invalidation on mount (Q11/G4)** — mounting mid-conversation may break a provider's cached prefix; G4 decides whether mounted definitions live in a separate cache segment via `_apply_cache_hints`.
- **Per-deployment blob backend (Q8)** — two backends double the storage matrix; the ACL/TTL/dedup logic lives in the ABC and backends only move bytes, so the conformance tests run once per backend over the same suite.
- **Encryption at rest** — HR data classes are encrypted in the blob store (Fernet via `cryptography`); the key comes from `SQUAWK_BLOB_KEY`; losing it makes blobs unreadable (documented operator risk).
- **Name collisions** — `Artifact` ×3, `ArtifactStore` ×2, `CapabilityEntry`: the nouns fixed here (`ArtifactHandle`, `HandleDescriptor`, `SquawkCapability`, `SquawkBlobStore`) are not renegotiable at task time.
- **`MCPServerConfig` field removal** is a hard cut: a YAML still carrying `grpc_*` keys fails validation if the model forbids extras; the changelog entry names the keys.
- **Taxonomy warning** — `ai-parrot-squawk` is not in `KNOWN_PROJECTS` (`scripts/sdd/sdd_meta.py`) and `parse_taxonomy` warns until sdd-tooling adds it (one-line follow-up outside this feature).
- **`polars` is importable by accident** (1.27.1 transitively installed) — AC17 greps for it.

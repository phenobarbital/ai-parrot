# Feature Specification: Brief Worktrees Survive the Worktree-Root Migration

**Feature ID**: FEAT-837
**Date**: 2026-11-07
**Author**: Jesus Lara (with Claude)
**Status**: approved
**Target version**: 2.1.3

---

## 1. Motivation & Business Requirements

### Problem Statement

FEAT-802 moved the SDD worktree root from `.claude/worktrees/` to
`.parrot/worktrees/`. On 2026-11-07 the feature worktrees were migrated, but
the brief worktree `hotfix-NAV-7762-ecotank-endcap-rows-new-cycle` disappeared:
the legacy directory was empty, git had no admin entry for it, and nothing was
created under the new root. The branch survived (local == origin). An
`sdd-worker` had already been launched inside that worktree, so any
uncommitted edits were lost (`issue:1b8289182630`).

Two gaps made this possible and made recovery manual:

1. **The migration recipe is blind to live workers.** `legacy_migration_recipe()`
   (`parrot/sdd/config.py`) emits `mv` + `git worktree repair` for every
   registered legacy worktree, with no check for a process running inside it,
   and no check afterwards that each destination is still a registered
   worktree. Moving a tree out from under a live sandboxed worker (whose
   sandbox paths are baked to the old absolute path) breaks the worker and can
   lose its work; a failed repair is silent.
2. **The launcher cannot recover an orphaned brief branch.**
   `feature_launcher._resolve_briefs()` only scans existing worktrees. When the
   worktree is gone but its `hotfix-<KEY>-*` / `fix-<KEY>-*` branch survives,
   `parrot sdd launch worker <KEY>` fails with
   `could not uniquely resolve feature '<KEY>'`, and
   `parrot sdd worktree ensure --brief-key` cannot reattach an existing branch.
   The operator has to run `git worktree add` by hand.

The root cause of the removal itself is not verified (an agent session ran the
migration per entry). This feature closes both gaps so the same sequence can
neither silently lose a live tree nor strand its branch.

### Goals

- G1: `legacy_migration_recipe()` refuses (raises `ValueError`) when any
  legacy worktree it would move has a live process inside it, naming the path
  and the PIDs. `parrot self doctor` and `parrot sdd install` already render
  that `ValueError` as "cannot generate a safe migration recipe: …".
- G2: The recipe ends with a per-destination check that each moved tree is a
  working git checkout after `git worktree repair`, failing loudly otherwise.
- G3: When no worktree holds a brief matching `<KEY>`, `resolve_feature()`
  looks for exactly one `hotfix-<KEY>-*` / `fix-<KEY>-*` branch (local, or on
  `origin`) that no worktree has checked out, re-attaches it under the current
  worktree root with `git worktree add`, and resolves the brief from it.

### Non-Goals (explicitly out of scope)

- Finding out which agent/session removed the NAV-7762 worktree.
- Changing `ensure_worktree --brief-key` to reattach existing branches.
- Migrating unregistered (orphan) directories under `.claude/worktrees/`.
- Re-attaching a branch that has no brief index (`sdd/briefs/*.index.json`):
  after re-attaching, resolution still requires the index, as today.

## 2. Architectural Design

### Overview

Two independent, small changes:

- **Module 1 (`parrot/sdd/config.py`)**: before building the recipe,
  `legacy_migration_recipe()` asks
  `parrot.sdd.scripts.remove_worktree.live_processes_in()` (lazy import —
  `remove_worktree` imports `config` at module level) for each topmost legacy
  path. Any hit raises `ValueError`. After the `git worktree repair` line the
  recipe appends one `git -C <dest> rev-parse --git-dir >/dev/null || { echo
  …; exit 1; }` line per destination.
- **Module 2 (`parrot/flows/dev_loop/feature_launcher.py`)**: a new
  `_reattach_brief_branch(primary, key)` is called by `resolve_feature()` when
  `_resolve_briefs()` returns nothing. It stays standard-library only (the
  file runs as a `python -S` script in the tmux child): every git call goes
  through the `_run` seam, and the worktree root comes from
  `sys.executable -m parrot.sdd.scripts.worktree_root --root <primary>`, the
  same out-of-process pattern `ensure_feature_worktree()` uses.

### Component Diagram

```
parrot self doctor / parrot sdd install
        └─> legacy_worktrees() ─> legacy_migration_recipe()
                                     ├─ live_processes_in(path)  [NEW guard → ValueError]
                                     └─ recipe … + rev-parse check per destination [NEW]

parrot sdd launch worker <KEY>
        └─> resolve_feature()
              ├─ feature indexes
              ├─ _resolve_briefs()            (existing worktrees)
              └─ _reattach_brief_branch()     [NEW: branch → git worktree add → _resolve_briefs()]
```

### Integration Points

| Existing Component | Integration Type | Notes |
|---|---|---|
| `remove_worktree.live_processes_in` | called (lazy import) | the same `/proc/<pid>/cwd` check `/remove-worktree` uses |
| `parrot.sdd.scripts.worktree_root` | subprocess | prints the resolved root; read-only |
| `doctor._check_sdd` / `installer` | unchanged | already render recipe `ValueError` text |

### Data Models

### New Public Interfaces

None public. One private helper: `feature_launcher._reattach_brief_branch`.

## 3. Module Breakdown

#### Delegation-eligible modules

Both modules are small and independent; either can be delegated.

### Module 1: Live-process guard + post-move check in the migration recipe

- **Path**: `packages/ai-parrot/src/parrot/sdd/config.py`
- **Responsibility**: in `legacy_migration_recipe()`, after the `topmost`
  list is computed and before any line is built, for each topmost old path
  call `live_processes_in(old_path)`; if non-empty raise
  `ValueError(f"legacy worktree has {n} live process(es) inside, wait for them to exit: {old_path} (pids: …)")`.
  After the existing `git -C <root> worktree repair …` line, append for every
  destination in `mappings` a line
  `git -C <dest> rev-parse --git-dir >/dev/null || { echo <msg> >&2; exit 1; }`
  where `<msg>` is the shell-quoted `error: migrated worktree is not a git checkout: <dest>`.
  Update the docstring (`Raises:`).
- **Tests**: `packages/ai-parrot/tests/sdd/test_config.py` — guard raises with
  a live process (monkeypatch `remove_worktree.live_processes_in`); recipe
  shape includes the per-destination check; the existing execute test still
  passes (real git, no live process).

### Module 2: Re-attach an orphaned brief branch in the launcher

- **Path**: `packages/ai-parrot/src/parrot/flows/dev_loop/feature_launcher.py`
- **Responsibility**:
  - `_reattach_brief_branch(primary: Path, key: str) -> list[FeatureRef]`:
    1. `git for-each-ref --format=%(refname) refs/heads refs/remotes/origin`
       via `_run`; strip `refs/heads/` / `refs/remotes/origin/`; keep names
       matching `^(hotfix|fix)-<re.escape(key)>-.+$` case-insensitively;
       dedupe (local and origin copies are one candidate, local preferred).
    2. Drop candidates already checked out (`branch refs/heads/<name>` lines
       of `git worktree list --porcelain`).
    3. Zero candidates → `[]` (caller raises the existing exit-2 error).
       More than one → `LaunchError(2, "ambiguous brief branches for '<key>': a, b")`.
    4. Root: `_run([sys.executable, "-m", "parrot.sdd.scripts.worktree_root", "--root", str(primary)])`,
       `_require` it, take stripped stdout. Destination `<root>/<branch>`; if
       it exists → `LaunchError(2, "cannot re-attach <branch>: <dest> already exists")`.
    5. Local branch exists → `git worktree add <dest> <branch>`; origin-only →
       `git worktree add --no-track -b <branch> <dest> origin/<branch>`;
       `_require` the result.
    6. Print `launch-worker: re-attached brief branch <branch> at <dest>` to
       stderr and return `_resolve_briefs(primary, key)`.
  - `resolve_feature()`: when `_resolve_briefs()` returns no match, call
    `_reattach_brief_branch()`.
  - Update the `_resolve_briefs` / `FeatureRef.worktree` comments that say a
    brief worktree is never re-created to say it may be re-attached from its
    surviving branch.
- **Tests**: `packages/ai-parrot/tests/sdd/test_sdd_launch.py` — fake `_run`:
  single local branch re-attached (asserts the `worktree add` argv and the
  resolved ref); origin-only branch uses `--no-track -b`; two candidates →
  exit 2; branch already checked out → exit 2 "could not uniquely resolve";
  existing destination → exit 2; no branch → original exit-2 message.

## 7. Implementation Notes & Constraints

- `live_processes_in` reads `/proc`; on non-Linux it iterates nothing and
  returns `[]` (the guard is a no-op there, same as `/remove-worktree`).
- Shell-quote every path in recipe lines with `shlex.quote`.
- Keep `feature_launcher.py` stdlib-only (AC5).

## 8. Risks

- The guard also refuses when the operator's own shell sits inside a legacy
  worktree — intended: moving a directory under a live shell is unsafe.
- Re-attaching is a new write in a launcher that previously never created a
  brief worktree; it is limited to a branch that already exists and a
  destination that does not.

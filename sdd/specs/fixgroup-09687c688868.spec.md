## 1. Motivation & Business Requirements

> Ledger-driven fix (`/sdd-fix`, fixgroup:09687c688868). Resolves
> `issue:66599d4e8c84` (major, tech_debt) — "22 pre-existing failures in
> packages/ai-parrot/tests/knowledge/wiki + bookstore".

### Problem Statement

`packages/ai-parrot/tests/knowledge/wiki/` is the package-local twin of the
CI-run `tests/knowledge/wiki/` tree. CI never runs it, but the merge-tier
selector (`coder_run_validation(tier="merge")`) does for any wiki change, so
its red tests keep every wiki feature's merge gate red (the issue's core
complaint).

Measured on `dev` @ `f3d22f21f` (2026-10-18), with `/tmp` clean, the issue's
22 failures reduce to **9 real test defects + 3 environment-gated tests**:

| Cluster | Tests | Cause (verified) |
|---|---|---|
| A. Stale tool surface | `test_mcp_server.py::test_initialize_and_list_tools`, `test_mcp_server_namespaces.py::{test_no_namespaces_keeps_a_plain_store,test_namespace_is_injected}`, `test_mcp_server_vault.py::test_no_vault_keeps_base_tool_set` | Each file hardcodes the 8-tool surface of FEAT-450 days; the local stdio surface is the 13-tool `LOCAL_NO_LEDGER` already frozen in `test_tool_surface_golden.py:15` (structural + decision tools added by FEAT-498/578). |
| B. Stale store kwargs | `test_mcp_server.py::test_sqlite_backend_unaffected_by_arango_branch` | Asserts `kwargs == {}`; `create_wiki_mcp_server` now passes `sqlite_policy=sqlite_policy_from_config(config)` (`mcp_server.py:194`). |
| C. Stale installer contract | `test_installer_mcp.py::{test_install_creates_mcp_json,test_install_updates_stale_entry}` | `assets.mcp_json_entry` resolves an **absolute** binary path by design (TASK-3212, `assets.py:119-125`); a `wikitoolkit` entry whose command does not end with `wikitoolkit` is *foreign* and intentionally left untouched (`installer.py:731`, `_is_wikitoolkit_entry` at `installer.py:753`). |
| D. Non-hermetic CLI tests | `test_cli.py::TestIngestModelResolutionDetectionFallback::{test_both_unset_uses_detection,test_auto_detected_construction_failure_degrades_cleanly}` | `_resolve_ingest_model_ids` (`cli.py:5247`) reads `WIKI_MODEL` through `_env_setting` → `resolve_setting`, which falls back to navconfig (`.env`). The developer `.env` sets `WIKI_MODEL` (line 601), so "both unset" is false and detection is skipped. |
| E. Environment-gated | `decisions/test_backend_parity.py` (3) | Needs live Postgres + ArangoDB or `ADR_PARITY_ALLOW_PARTIAL=1`; fails by design without them. **Not a code defect — out of scope (see §8).** |

Already gone since the issue was filed: the four `test_hook_startup.py`
failures (pass now), and `bookstore/test_integration_graph.py` (file no
longer exists in this tree).

A second, machine-level cause was also found: stray `/tmp/.git` and
`/tmp/.parrot/ledger` directories make `find_shared_root`/`find_project_root`
(`project.py:1519`) resolve *above* every `tmp_path`, which injects the
ledger tool namespace into "plain" servers and turned clusters A/B into 14
failures on this machine. Those directories were moved aside
(`/tmp/.git.polluted-*`, `/tmp/.parrot-polluted-*`); no module in this group
recreates them. Guarding against it is a non-goal (see §7).

### Goals
- G1: clusters A–D pass on a clean `dev` checkout without network, services
  or developer `.env` values.
- G2: the local stdio tool surface is asserted from ONE shared constant,
  so the next tool addition updates one place (the golden test already
  owns the inventory; the other three files reuse it).
- G3: the installer tests pin the *intended* contract (absolute path;
  managed-but-stale entry refreshed; foreign entry preserved).

### Non-Goals (explicitly out of scope)
- No production code changes under `parrot/knowledge/wiki/` — every cluster
  is a stale or non-hermetic *test*; the behaviours are intended.
- Cluster E (backend parity) — see §8.
- The `/tmp` pollution source; the CI-run root twin `tests/knowledge/wiki/`
  (green; does not contain these modules).
- Deleting or merging the two wiki test trees.

## 2. Architectural Design

### Overview

Test-only change in `packages/ai-parrot/tests/knowledge/wiki/`: one new
helper module holding the frozen tool inventories, four tests pointed at it,
two installer tests rewritten to the FEAT-485/TASK-3212 contract, and the
ingest-detection test class made hermetic by patching the CLI's env reader.

### Integration Points

| Existing Component | Integration Type | Notes |
|---|---|---|
| `test_tool_surface_golden.py` (`LOCAL_NO_LEDGER`, `LEDGER`, `BULK`) | moved | inventories move to `_tool_surface.py`; golden test imports them |
| `test_mcp_server.py:89`, `test_mcp_server_namespaces.py:20`, `test_mcp_server_vault.py:17` | modified | hardcoded sets → `set(LOCAL_NO_LEDGER)` |
| `test_mcp_server.py:182` | modified | `kwargs == {}` → exactly `{"sqlite_policy"}` and no arango keys |
| `test_installer_mcp.py:40,63` | modified | absolute-path + managed/foreign semantics |
| `test_cli.py:298` (`_invoke_ingest`) | modified | patch `wiki_cli._env_setting` to an `os.environ`-only reader |

### New Public Interfaces

None (test helper module only).

#### Delegation-eligible modules

### Module 1: Shared tool surface (clusters A + B)
- **Path**: `packages/ai-parrot/tests/knowledge/wiki/_tool_surface.py` (new),
  `test_tool_surface_golden.py`, `test_mcp_server.py`,
  `test_mcp_server_namespaces.py`, `test_mcp_server_vault.py`
- **Responsibility**: one frozen inventory of the local stdio surface.
- **Interface Skeleton**:
  ```python
  # packages/ai-parrot/tests/knowledge/wiki/_tool_surface.py
  """Frozen wiki MCP tool inventories shared by the surface tests (FEAT-700)."""
  LOCAL_NO_LEDGER: list[str] = sorted([...13 names verbatim from test_tool_surface_golden.py:15-31...])
  LEDGER: list[str] = sorted([...7 names...])
  BULK: list[str] = sorted([...4 names...])
  ```
  `test_tool_surface_golden.py` keeps its two tests and imports the three
  names (the `pytest.importorskip` stays, before the parrot imports).
  The three stale files replace their literal sets with
  `set(LOCAL_NO_LEDGER)`; `test_mcp_server.py:182` becomes
  `assert set(captured["kwargs"]) == {"sqlite_policy"}`.

### Module 2: Installer contract (cluster C)
- **Path**: `packages/ai-parrot/tests/knowledge/wiki/test_installer_mcp.py`
- `test_install_creates_mcp_json`: `command.endswith("wikitoolkit")`,
  `args == ["mcp"]`, `env == {}`.
- `test_install_updates_stale_entry`: seed
  `{"command": "/old/venv/bin/wikitoolkit", "args": ["mcp"], "env": {}}`
  (managed shape, stale path) → after install the entry equals
  `assets.mcp_json_entry(repo_root)`.
- New `test_install_leaves_foreign_wikitoolkit_entry_untouched`: seed
  `{"command": "old-stale-command"}` → unchanged after install.

### Module 3: Hermetic ingest detection (cluster D)
- **Path**: `packages/ai-parrot/tests/knowledge/wiki/test_cli.py`
- In `_invoke_ingest`, add
  `patch.object(wiki_cli, "_env_setting", side_effect=lambda name: os.environ.get(name) or None)`
  inside the existing `with`-block so the five tests in the class read ONLY
  the process environment (the three env-driven tests keep passing because
  they set the variables through `monkeypatch.setenv`).

## 7. Implementation Notes & Constraints

### Patterns to Follow
- Keep `pytest.importorskip("parrot.mcp.transports.streamable_http")` in the
  golden test above the `parrot.*` imports; `_tool_surface.py` must import
  nothing from `parrot` so the other files can import it unconditionally.
- `test_mcp_server_vault.py` already imports helpers from
  `tests.knowledge.wiki.test_mcp_server`; import the new module the same way
  (`from tests.knowledge.wiki._tool_surface import LOCAL_NO_LEDGER`).

### Known Risks / Gotchas
- **`/tmp` pollution**: a `.git` or `.parrot` directory directly under the
  pytest basetemp parent (`/tmp`) re-breaks clusters A/B via
  `find_shared_root`. If the suite is red with ledger tools present in a
  "plain" server, check `ls -d /tmp/.git /tmp/.parrot` first.
- `resolve_setting` preserves falsey values; the patched reader must return
  `None` for missing/empty names so the "both unset" branch is reached.

### External Dependencies
None.

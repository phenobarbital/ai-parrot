# Feature Specification: Propagate the E2E plan's live budget to the fixture agent

**Feature ID**: FEAT-701
**Date**: 2026-10-18
**Author**: Claude (agent:sdd-fix)
**Status**: approved
**Target version**: 0.30.x

---

## 1. Motivation & Business Requirements

> Ledger-driven fix (`/sdd-fix`, fixgroup:27d350c92624). Resolves
> `issue:5076d67c9758` (major, bug) — "Live plan budget is not passed to the
> fixture agent".

### Problem Statement

`E2EPlan.budget` (`LiveBudget`: model, max_calls, max_output_tokens,
max_request_bytes, timeout_s — `models.py:120-135`) is validated by
`load_plan` and documented as "the aggregate budget that bounds every
generation attempt across the run" (`tests/e2e/plans/live.md:49`). It never
reaches the code that generates:

1. `run_plan` wraps the plan in `_LiveBudgetContext` (`runner.py:50,80`) and
   `_run_scenario` discards it (`_ = live_budget`, `runner.py:183`); the
   pytest child env (`runner.py:192-200`) carries run/owner/results vars only.
2. The live scenario (`tests/e2e/test_mcp_agent_live.py`) starts the
   `mcp-agent` target itself; the adapter forwards only
   `FORWARDED_ENV_VARS` (`live.py:106-112`, `targets/mcp.py:587-590`) into
   the `python -m parrot.e2e.live` child.
3. Inside that child, `_ensure_agent` (`live.py:449-452`) calls
   `require_live_opt_in()` and `build_live_generation_budget(opt_in)` with
   **no `budget=`**, so `LiveBudget()` defaults apply: `live.md`'s
   `timeout_s: 90` is enforced as 60, and any per-plan ceiling change is a
   no-op on the paid run.

### Goals
- G1: the validated plan budget reaches the fixture agent's one run-scoped
  `GenerationBudget` unchanged (ceilings AND model/max_calls defaults that
  `require_live_opt_in` resolves env overrides against).
- G2: one transport, declared once: a single env var carried by the runner
  into pytest and by the adapter into the fixture child.
- G3: fail closed on a malformed budget payload (configuration error, never
  silent defaults).

### Non-Goals (explicitly out of scope)
- No change to `GenerationBudget` itself, to the supervisor's env
  stripping, or to `E2E_MODEL`/`E2E_MAX_LLM_CALLS` override precedence.
- No budget hook on the adapter protocol (`targets/base.py`); the env var
  is the hand-off.
- No change to `tests/e2e/plans/live.md`.

## 2. Architectural Design

### Overview

`parrot.e2e.live` gains `LIVE_BUDGET_ENV = "PARROT_E2E_LIVE_BUDGET"` (JSON
of `LiveBudget`), appended to `FORWARDED_ENV_VARS`, plus
`resolve_plan_budget()` that parses it (defaults when absent, `E2EConfigError`
when malformed). `_ensure_agent` resolves it once and passes it as `budget=`
to both `require_live_opt_in` and `build_live_generation_budget`. The runner
turns `_LiveBudgetContext` into the producer: `child_env()` returns
`{LIVE_BUDGET_ENV: plan.budget.model_dump_json()}` and `_run_scenario`
merges it into the pytest child's env. The adapter needs no change because
it already forwards every `FORWARDED_ENV_VARS` entry.

```
run_plan ──_LiveBudgetContext(plan).child_env()──▶ pytest child env
   └─ test_mcp_agent_live ──build_mcp_agent_adapter().prepare()──▶ FORWARDED_ENV_VARS
                                  └─ parrot.e2e.live child ──resolve_plan_budget()──▶ _ensure_agent
```

### Integration Points

| Existing Component | Integration Type | Notes |
|---|---|---|
| `_LiveBudgetContext` (`runner.py:50`) | modified | adds `child_env()`; docstring updated |
| `_run_scenario` env block (`runner.py:192-200`) | modified | `**live_budget.child_env()` replaces `_ = live_budget` |
| `FORWARDED_ENV_VARS` (`live.py:106`) | modified | `LIVE_BUDGET_ENV` appended |
| `_ensure_agent` (`live.py:449`) | modified | `budget=` wired on both calls |

### Module 1: Live budget hand-off
- **Path**: `packages/ai-parrot-server/src/parrot/e2e/live.py`,
  `packages/ai-parrot-server/src/parrot/e2e/runner.py`
- **Interface Skeleton**:
  ```python
  # live.py — after E2E_MAX_LLM_CALLS_ENV (line ~99)
  #: JSON-serialized ``LiveBudget`` the runner hands to every live child
  #: (pytest → mcp-agent adapter → this module's fixture agent).
  LIVE_BUDGET_ENV = "PARROT_E2E_LIVE_BUDGET"

  FORWARDED_ENV_VARS: tuple[str, ...] = (
      PARROT_TEST_E2E_ENV, PARROT_TEST_REAL_LLM_ENV, GOOGLE_API_KEY_ENV,
      E2E_MODEL_ENV, E2E_MAX_LLM_CALLS_ENV, LIVE_BUDGET_ENV,
  )

  def resolve_plan_budget(env: Optional[Mapping[str, str]] = None) -> LiveBudget:
      environ = env if env is not None else os.environ
      raw = environ.get(LIVE_BUDGET_ENV)
      if not raw:
          return LiveBudget()
      try:
          return LiveBudget.model_validate_json(raw)
      except ValueError as exc:  # pydantic.ValidationError subclasses ValueError
          raise E2EConfigError(f"{LIVE_BUDGET_ENV} is not a valid LiveBudget payload: {exc}", reason_code="invalid_budget") from exc

  # _ensure_agent (live.py:449-452)
  plan_budget = resolve_plan_budget()
  opt_in = require_live_opt_in(budget=plan_budget)
  budget = build_live_generation_budget(opt_in, budget=plan_budget)
  ```
  ```python
  # runner.py
  from parrot.e2e.live import LIVE_BUDGET_ENV

  @dataclass
  class _LiveBudgetContext:
      plan: E2EPlan
      def child_env(self) -> dict[str, str]:
          """The one env entry that carries the validated plan budget into every live child."""
          return {LIVE_BUDGET_ENV: self.plan.budget.model_dump_json()}

  # _run_scenario: remove `_ = live_budget`; env={**os.environ, ..., "PARROT_TEST_E2E": "1", **live_budget.child_env()}
  ```

## 5. Acceptance Criteria

- [ ] AC1: with `live.md`'s budget, the fixture agent's `GenerationBudget`
      has `timeout_s == 90`, `max_output_tokens == 512`,
      `max_request_bytes == 16384`, `max_calls == 4` (unit-level proof via
      `resolve_plan_budget` + the two builders).
- [ ] AC2: the runner's pytest child env carries `PARROT_E2E_LIVE_BUDGET`
      equal to `plan.budget.model_dump_json()`.
- [ ] AC3: `LIVE_BUDGET_ENV` is in `FORWARDED_ENV_VARS` (adapter forwards it
      without code change).
- [ ] AC4: a malformed payload raises `E2EConfigError(reason_code="invalid_budget")`
      before any client construction; an absent payload yields defaults.
- [ ] AC5: `tests/unit/e2e/test_live_gate.py`, `test_runner.py` and
      `test_mcp_targets.py` pass.

## 7. Implementation Notes & Constraints

### Patterns to Follow
- `live.py` keeps provider imports lazy; `resolve_plan_budget` uses only
  `os`, `LiveBudget` and `E2EConfigError`, all already imported.
- Add `"LIVE_BUDGET_ENV"` and `"resolve_plan_budget"` to `__all__`.
- The runner may import `parrot.e2e.live` at module scope: its module-level
  imports are `argparse/asyncio/contextlib/logging/os/signal/sys`, pydantic,
  `parrot.e2e.errors` and `parrot.e2e.models` only.

### Known Risks / Gotchas
- The supervisor strips credential vars from children; the budget var is
  not a credential and passes through, but the adapter's explicit forward
  list is still the contract — hence the `FORWARDED_ENV_VARS` entry.
- `test_mcp_targets.py` may pin the forwarded env keys; if it asserts an
  exact set, update that expectation (in scope: it is a test of the same
  contract).

### External Dependencies
None.

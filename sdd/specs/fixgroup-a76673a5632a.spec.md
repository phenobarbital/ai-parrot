## 1. Motivation & Business Requirements

### Problem Statement

FEAT-802 (worktree root under `.parrot/`) shipped a legacy-worktree migration
note that tells users to run "the recipe `parrot doctor` prints". **No such
top-level command is registered.** The check and the migration recipe live
under `parrot self doctor`:

```
$ parrot doctor --help
Error: No such command 'doctor'.

$ parrot self doctor --help
Usage: parrot self doctor [OPTIONS]
  Diagnose the managed runtime, host configs, toolkit requirements and SDD
  readiness.
```

A user who follows the shipped instruction hits a hard CLI error with no
pointer to the correct command. The wrong name is in the packaged installer
asset (so every repository `parrot sdd install` touches inherits it), in the
installed host twins, in the `ensure_worktree` runtime error message, and in
two user-facing install docs.

Tracked as `issue:f90b8c2c3472` (`tech_debt`, `low`, discovered from
`spec:FEAT-802`).

### Goals

- Every shipped instruction and error message names `parrot self doctor`.
- `tests/sdd_scripts/test_ensure_worktree.py` asserts the corrected string, so
  the error message is regression-guarded.
- The TASK-5183 guard test (`test_no_legacy_worktree_root_remains`) keeps
  passing: any line naming `.claude/worktrees` still carries
  `git worktree repair` on the same line.

### Non-Goals (explicitly out of scope)

- Registering a top-level `parrot doctor` alias. `parrot status` is already
  taken by the agentd daemon and the project decided against top-level
  `env`/`doctor` commands (TASK-4080, TASK-4091, TASK-4095). The command name
  is correct; only the prose is wrong.
- Rewriting historical SDD artifacts under `sdd/specs/`, `sdd/proposals/` or
  `sdd/tasks/completed/`. Those record what was decided at the time and are
  never retro-edited.
- Any behavioural change to `parrot self doctor`, `parrot sdd install` or
  `ensure_worktree`'s legacy-root refusal logic.

## 7. Implementation Notes & Constraints

- **The guard test is the trap.** `tests/sdd_scripts/test_command_contracts.py::test_no_legacy_worktree_root_remains`
  scans `.md`/`.toml`/`.sh` under `.claude/`, `.agent/`, `.agents/` and
  `packages/ai-parrot/src/parrot/sdd/_assets/`, plus `CLAUDE.md`, and fails on
  any line containing `.claude/worktrees` that does **not** also contain
  `git worktree repair`. The two long lines being edited satisfy that today —
  keep both substrings on the same physical line; do not reflow or wrap.
- **Asset / twin parity.** The `_assets/claude/rules/worktree-management.md`
  line and the installed `.claude/rules/worktree-management.md` line are
  identical today. Apply the identical edit to both so the installer does not
  report drift.
- **Do not touch** `sdd/specs/*`, `sdd/proposals/*` or `sdd/tasks/completed/*`.
  Those mention `parrot doctor` as historical record (including
  `sdd/specs/parrot-installer.spec.md`, where it appears inside a struck-through
  "does not exist" list — correcting it there would invert its meaning).
- **The `wiki/` page is source, not generated**: `sdd/config.json` sets
  `techwiki.source_dir: "wiki"`, so `wiki/operations/install/global-runtime.md`
  is edited directly.
- `.claude/` files may need `git add -f` depending on the ignore rules in
  effect; verify with `git status` before committing.

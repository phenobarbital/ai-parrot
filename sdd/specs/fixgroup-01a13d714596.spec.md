# Feature Specification: Bump dompurify past the SAFE_FOR_TEMPLATES shadow-root bypass (GHSA-cg2g-xh64-v4q7)

**Feature ID**: FEAT-741
**Date**: 2026-10-25
**Author**: agent:sdd-fix
**Status**: approved
**Target version**: 0.29.x

> Ledger-driven fix (`/sdd-fix`). Group `fixgroup:01a13d714596`,
> issue `issue:98566c204186` (vulnerability, critical, discovered-from review:dependabot-alert-237).

---

## 1. Motivation & Business Requirements

### Problem Statement

The admin UI (`packages/ai-parrot-server/ui`) depends on `dompurify ^3.4.16`
(`package.json:39`), pinned to `3.4.16` in `pnpm-lock.yaml:1312,3284`.
GHSA-cg2g-xh64-v4q7 (critical, CVSSv4 9.2, GitHub Dependabot alert #237) affects
every `dompurify` release `>=3.4.4,<=3.4.16`: when `SAFE_FOR_TEMPLATES: true` is
combined with a DOM-returning sanitize mode (`RETURN_DOM`, `RETURN_DOM_FRAGMENT`,
or `IN_PLACE`), a template expression split across text-node siblings inside an
*attached shadow root* survives sanitization — the post-walk re-scrub
(`_scrubTemplateExpressions`) recurses into `<template>.content` but never into
shadow roots — so a downstream template engine can evaluate an attacker-chosen
expression (XSS / template injection). The fix ships in `dompurify@3.4.17`
(published on the npm registry; confirmed present).

The only call site in this repo, `packages/ai-parrot-server/ui/src/lib/utils/markdown.ts`
(`sanitize()` wrapping `DOMPurify.sanitize(html, config)`), does not set
`SAFE_FOR_TEMPLATES`, `RETURN_DOM`, `RETURN_DOM_FRAGMENT`, or `IN_PLACE` today, so
this specific path is not currently exploitable — but `dompurify` is a direct
runtime dependency flagged critical by Dependabot, the fix is a clean patch bump
with no documented breaking change between 3.4.16 and 3.4.17, and Dependabot will
keep re-raising the alert on every scan of `main` until the pin moves.

### Goals

- G1. `packages/ai-parrot-server/ui` resolves `dompurify` to `>=3.4.17` in both
  `package.json` and `pnpm-lock.yaml`, clearing Dependabot alert #237.
- G2. No other dependency in the lockfile regresses as a side effect of the
  `pnpm install` that regenerates the lock entry.
- G3. The admin UI's existing markdown-sanitization behavior (and its tests) are
  unchanged — this is a patch-version security bump, not a behavior change.

### Non-Goals (explicitly out of scope)

- Adopting `SAFE_FOR_TEMPLATES`/`RETURN_DOM`/`IN_PLACE` anywhere — the call site
  stays as it is; this spec only moves the vulnerable version out of range.
- Any other Dependabot alert or dependency in the lockfile.
- Changes to `markdown.ts`'s sanitize config or call sites.

## 2. Architectural Design

### Overview

Pure dependency-version change: bump the `dompurify` version range in
`package.json`, then regenerate `pnpm-lock.yaml` so the resolved/locked version
and its integrity hash move to `3.4.17` (or later). No source code changes.

### Component Diagram

```
packages/ai-parrot-server/ui/package.json   (dompurify ^3.4.16 → ^3.4.17)
      │
      └─ pnpm install  ──→  pnpm-lock.yaml   (dompurify@3.4.16 → dompurify@3.4.17,
                                               new integrity hash, both importer
                                               and packages entries)
```

### Integration Points

| Existing Component | Integration Type | Notes |
|---|---|---|
| `packages/ai-parrot-server/ui/src/lib/utils/markdown.ts` | consumer, unchanged | imports `DOMPurify` from `dompurify`; `sanitize()` call signature is stable across the 3.4.x line |
| `packages/ai-parrot-server/ui/package.json` | edit | version range for the `dompurify` dependency |
| `packages/ai-parrot-server/ui/pnpm-lock.yaml` | regenerate | resolved version + integrity hash |

### Data Models

None — no new types or interfaces.

### New Public Interfaces

None.

## 7. Implementation Notes & Constraints

### Patterns to Follow

- Package manager for the admin UI is `pnpm` (see `.claude/rules/codebase-conventions.md`
  § TypeScript + Svelte) — never hand-edit `pnpm-lock.yaml`.

### Known Risks / Gotchas

- `pnpm install` may also touch unrelated transitive entries if the lockfile
  was already slightly behind `package.json`; AC4 guards against an
  unexpectedly wide diff — if one shows up, scope the commit to the
  `dompurify`-related lines only and flag the rest separately rather than
  committing an unrelated drive-by lockfile churn.

### External Dependencies

- `dompurify@3.4.17` (npm) — confirmed published, fixes GHSA-cg2g-xh64-v4q7.

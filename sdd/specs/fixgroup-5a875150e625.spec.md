# FEAT-766 — Closeout hooks follow-up hardening

**Discovered-from**: `issue:1ac97711d2bd`

## Background

FEAT-764 introduced `/sdd-done` closeout hooks (`run_closeout_hooks.py`,
`closeout_builtins.py`, `closeout_hooks_config.py`). A post-merge review
surfaced eight follow-up items across the implementation and the three
workflow twins (`.agent/workflows/sdd-done.md`, `.claude/commands/sdd-done.md`,
`.agents/skills/sdd-done/SKILL.md`).

## Scope

### Python code hardening (run_closeout_hooks.py + closeout_builtins.py)

1. **Artifact confinement** — `_outcome_path` builds a filesystem path from
   `feat_id` without validation; a malicious or malformed id (e.g. `../../../x`)
   could escape the artifact root. Validate `feat_id` against `_NAME_RE`-like
   pattern (alphanumeric, hyphens, dots) before use; also reject `..` and
   absolute paths in `_glob_artifacts`'s pattern argument.

2. **Atomic persist** — `_persist` docstring says "atomically" but uses
   `write_text`. Replace with temp-file + `os.replace` for crash-safety.

3. **pre_pr short-circuit** — a blocking `pre_pr` failure does not stop later
   hooks from running; the loop continues past a failed blocker. Add
   short-circuit logic: if a blocking hook fails/times out in `pre_pr`, skip
   remaining hooks.

4. **Deduplicate `_Defaulting`** — the helper class is copy-pasted in both
   `run_closeout_hooks.py` and `closeout_builtins.py`. Move it to
   `closeout_hooks_config.py` and import from both consumers.

5. **Missing docstrings** — `_result`, `_push_ntfy`, `_push_gotify` in
   `closeout_builtins.py` lack docstrings.

6. **Module-level assert** — `assert set(_PUSH) == set(PUSH_PROVIDERS)` in
   `closeout_builtins.py` is stripped under `python -O`. Replace with a
   runtime check that raises `RuntimeError`.

7. **`run_event`/`record` unused `root` parameter** — `run_event` accepts
   `root` then immediately `del root`. The `record` function passes `root` to
   `load_hooks(root)` which is correct, but `run_event` receives `cfg`
   already-loaded so the parameter is dead. Remove the dead parameter from
   `run_event` (and update callers: `main()`) to match spec M2. Keep `root`
   on `record` and `finalize`.

### Workflow twin updates

8. **Antigravity twin** (`.agent/workflows/sdd-done.md`) — Step 10 still
   documents `--resolve-jira` as a manual procedural step; FEAT-764 moved
   Jira transition to the `jira.transition` builtin hook. Add a note that
   Step 10 is now handled by the closeout-hooks subsystem and the manual
   procedure is retained only as a fallback reference.

9. **Codex twin** (`.agents/skills/sdd-done/SKILL.md`) — does not document
   the `--finalize` exit-1 branch: when `--finalize` is passed and the
   outcome has blocking failures, `main()` returns `EXIT_BLOCKING` (1).

10. **`on_failure` / exit 3 in twins** — when `run_closeout_hooks.py` returns
    exit 3 (pending agents), neither twin documents how the caller should
    handle it. Add a note in both twins that exit 3 means agent hooks are
    pending and the caller should dispatch them, then `--record` each result,
    then `--finalize` to resolve any still-pending hooks.

## Out of Scope

- Changing the `HookSpec` model or config schema.
- Adding new builtins or events.
- Modifying `closeout_hooks_config.py` beyond hosting the shared `_Defaulting`.

## Acceptance Criteria

- AC-1: `_outcome_path` and `_glob_artifacts` reject path-traversal inputs.
- AC-2: `_persist` uses temp-file + `os.replace`.
- AC-3: `run_event` short-circuits after a blocking `pre_pr` failure.
- AC-4: `_Defaulting` is defined once in `closeout_hooks_config.py`.
- AC-5: `_result`, `_push_ntfy`, `_push_gotify` have one-line docstrings.
- AC-6: Module-level assert replaced with `RuntimeError` check.
- AC-7: `run_event` has no `root` parameter; callers updated.
- AC-8: Antigravity twin notes Step 10 hook delegation.
- AC-9: Codex twin documents `--finalize` exit-1 branch.
- AC-10: Both twins document exit 3 (pending agents) handling.
- AC-11: All existing tests pass; new tests cover items 1–3.

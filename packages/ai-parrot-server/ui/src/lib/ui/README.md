# UI Layer — CSS & Component Conventions

This document is the authoritative reference for styling and component patterns in
Navigator Frontend. All new components and CSS edits must follow these conventions.

> **TL;DR**: Use semantic tokens (`bg-primary`, `bg-card`) inside `internal/shadcn/ui/`.
> Use scale tokens (`bg-primary-600 dark:bg-primary-400`) in `components/` wrappers and
> page-level components. Never use hardcoded arbitrary values.

---

## Directory Structure

```
src/lib/ui/
├── internal/
│   └── shadcn/
│       ├── ui/          # AUTO-GENERATED — do not edit by hand
│       │   ├── button/
│       │   ├── card/
│       │   ├── dialog/
│       │   └── ...      # ~20 shadcn component directories
│       └── utils.ts     # cn() class-merge utility (manual)
└── components/          # MANUAL wrappers using bits-ui + Tailwind
    ├── AppDialog.svelte
    ├── AppDropdown.svelte
    ├── AppSheet.svelte
    ├── AppTabs.svelte
    ├── AppToggle.svelte
    ├── AppTooltip.svelte
    ├── SimpleTable.svelte
    └── index.ts
```

### `internal/shadcn/ui/` — auto-generated, do not edit

These files are generated by the `shadcn-svelte` CLI and updated with `npx shadcn-svelte@latest add <component>`.
They use **semantic tokens** (`bg-primary`, `bg-card`, `text-foreground`) which map to CSS vars defined in `app.css`.
Do not edit them directly — re-run the CLI to update or customize via the `cn()` override API.

### `components/` — manual wrappers, own these files

These are project-specific wrappers around `bits-ui` headless primitives.
They use **scale tokens** (`bg-primary-600 dark:bg-primary-400`) directly so they respond
to dark mode through Tailwind's `.dark` class mechanism.
Import all of them from the barrel: `import { AppDialog, AppToggle, SimpleTable } from '$lib/ui/components'`.

## Two-Layer Token Architecture

The styling system has two layers. Understanding which layer a file belongs to determines
which token style to use.

```
┌─────────────────────────────────────────────────────────────┐
│  Layer 1: Scale Tokens  (source of truth)                   │
│  Defined in app.css @theme block                            │
│                                                             │
│  --color-primary-400: #60a5fa  (Tailwind: bg-primary-400)  │
│  --color-primary-600: #2563eb  (Tailwind: bg-primary-600)  │
│  --color-secondary-100: #f1f5f9  (bg-secondary-100)        │
│  --color-secondary-800: #1e293b  (bg-secondary-800)        │
│  --color-secondary-200: #e2e8f0  (bg-secondary-200)        │
└───────────────────────────┬─────────────────────────────────┘
                            │ mapped to
┌───────────────────────────▼─────────────────────────────────┐
│  Layer 2: Semantic Tokens  (derived, theme-aware)           │
│  Defined in app.css :root + .dark                           │
│                                                             │
│  :root  { --primary: #2563eb; --muted: #f1f5f9; ... }      │
│  .dark  { --primary: #60a5fa; --muted: #1e293b; ... }      │
│                                                             │
│  Tailwind utilities: bg-primary, bg-muted, bg-card,        │
│  text-foreground, border-border, ring-ring, ...            │
└─────────────────────────────────────────────────────────────┘
```

### Semantic token reference

| Tailwind Class            | CSS Var                     | Light value | Dark value | Use for                        |
| ------------------------- | --------------------------- | ----------- | ---------- | ------------------------------ |
| `bg-primary`              | `var(--primary)`            | `#2563eb`   | `#60a5fa`  | Brand buttons, active states   |
| `text-primary-foreground` | `var(--primary-foreground)` | `#ffffff`   | `#ffffff`  | Text on `bg-primary` surfaces  |
| `bg-secondary`            | `var(--secondary)`          | `#f1f5f9`   | `#1e293b`  | Secondary buttons              |
| `bg-card`                 | `var(--card)`               | `#ffffff`   | `#020617`  | Card/panel surfaces            |
| `text-card-foreground`    | `var(--card-foreground)`    | `#0f172a`   | `#f8fafc`  | Text on card surfaces          |
| `bg-muted`                | `var(--muted)`              | `#f1f5f9`   | `#1e293b`  | Subdued backgrounds            |
| `text-muted-foreground`   | `var(--muted-foreground)`   | `#64748b`   | `#94a3b8`  | Placeholder / helper text      |
| `bg-background`           | `var(--background)`         | `#ffffff`   | `#020617`  | Page background                |
| `text-foreground`         | `var(--foreground)`         | `#0f172a`   | `#f8fafc`  | Body text                      |
| `border-border`           | `var(--border)`             | `#e2e8f0`   | `#1e293b`  | Dividers, input borders        |
| `ring-ring`               | `var(--ring)`               | `#3b82f6`   | `#3b82f6`  | Focus rings                    |
| `bg-accent`               | `var(--accent)`             | `#f1f5f9`   | `#1e293b`  | Hover states on ghost elements |

## Decision Tree: Which Class Should I Use?

```
Am I editing a file in internal/shadcn/ui/?
├── YES → Use SEMANTIC tokens only (bg-primary, bg-card, text-foreground, border-border)
│         These files are auto-generated. Only touch them via shadcn CLI.
│
└── NO → Am I writing a bits-ui wrapper in components/ or a page component?
         ├── YES, it's a wrapper in components/ →
         │       Use SCALE tokens with dark: variant
         │       e.g. bg-primary-600 dark:bg-primary-400
         │            text-secondary-900 dark:text-secondary-50
         │
         └── YES, it's a page/feature component →
                 Prefer SEMANTIC tokens — they are simpler and work in both modes.
                 bg-card, bg-muted, text-foreground, border-border
                 Fall back to scale tokens only when you need a specific shade.
```

## Code Examples

### Example 1 — shadcn component (semantic tokens only)

This is `internal/shadcn/ui/button/button.svelte`. Note: semantic tokens everywhere, no
scale tokens, no hardcoded hex values.

```svelte
<!-- internal/shadcn/ui/button/button.svelte — DO NOT EDIT DIRECTLY -->
<script lang="ts" module>
  export const buttonVariants = tv({
    variants: {
      variant: {
        default: "bg-primary text-primary-foreground hover:bg-primary/90 shadow-xs",
        secondary: "bg-secondary text-secondary-foreground hover:bg-secondary/80 shadow-xs",
        outline: "bg-background hover:bg-accent border shadow-xs",
        ghost: "hover:bg-accent hover:text-accent-foreground",
        destructive: "bg-destructive text-white shadow-xs",
      },
    },
  });
</script>
```

### Example 2 — App\* wrapper (scale tokens with dark: variant)

This is `components/AppToggle.svelte`. Note: scale tokens with explicit dark: modifiers,
using `bits-ui` primitives under the hood.

```svelte
<!-- components/AppToggle.svelte -->
<script lang="ts">
  import { Switch } from 'bits-ui';
  let { checked = $bindable(false), disabled = false, label }: {
    checked: boolean; disabled?: boolean; label?: string;
  } = $props();
</script>

<Switch.Root
  bind:checked
  class="bg-gray-300 data-[state=checked]:bg-primary-600
         dark:bg-gray-600 dark:data-[state=checked]:bg-primary-500
         focus:ring-primary-500 ..."
>
  <Switch.Thumb class="bg-white ..." />
</Switch.Root>
```

### Example 3 — Feature component (semantic tokens preferred)

A chat sidebar container that responds to dark mode without explicit `dark:` variants:

```svelte
<!-- CORRECT — uses semantic tokens, dark mode automatic -->
<div class="bg-card border-r border-border h-full shadow-sm">
  <header class="bg-muted/50 border-b border-border px-4 py-3">
    <h2 class="text-foreground font-semibold">Conversations</h2>
  </header>
  <!-- ... -->
</div>

<!-- WRONG — hardcoded, breaks dark mode -->
<div class="bg-white dark:bg-slate-800 border-r border-slate-200 dark:border-slate-700 h-full">
```

## Theme Store

Dark mode is managed by `src/lib/stores/theme.svelte.ts` (Svelte 5 runes, `.svelte.ts`).

```typescript
// Import
import { themeStore } from "$lib/stores/theme.svelte";

// Read reactive state (in a .svelte component)
let isDark = $derived(themeStore.isDark);
let theme = $derived(themeStore.currentTheme); // 'light' | 'dark'

// Mutate
themeStore.toggleDarkMode();
themeStore.setTheme("dark"); // sets + persists to localStorage
themeStore.setTheme("light", false); // sets without persisting (e.g. embed mode)

// On mount (layout.svelte)
$effect(() => {
  themeStore.init();
}); // reads localStorage, applies to <html>
```

The store applies two attributes to `<html>` on every theme change:

- `data-theme="light"` or `data-theme="dark"` — for DaisyUI/legacy compatibility
- `.dark` CSS class — for Tailwind dark mode variants

## Anti-Patterns

The following patterns are **forbidden** in all new code and must be replaced during refactors.

### 1. Hardcoded arbitrary color values

```svelte
<!-- FORBIDDEN -->
<div class="!bg-[#f9fafb] !text-slate-900">
<div style="background-color: #ffffff;">
<div class="bg-[#2563eb]">

<!-- CORRECT -->
<div class="bg-muted text-foreground">
<div class="bg-card">
<div class="bg-primary">
```

### 2. `!important` color overrides

`!important` (the `!` prefix in Tailwind v4) breaks dark mode because it overrides
the `.dark` class cascade. Never use it on color utilities.

```svelte
<!-- FORBIDDEN -->
<div class="!bg-white !text-black">

<!-- CORRECT -->
<div class="bg-card text-card-foreground">
```

### 3. `bg-white` / `bg-slate-*` in themed containers

These are scale tokens from the default Tailwind palette and do not respond to
the semantic token layer. They produce static colors in both light and dark modes.

```svelte
<!-- FORBIDDEN in any component that should support dark mode -->
<div class="bg-white dark:bg-slate-800">
<div class="bg-slate-50 dark:bg-slate-900">
<div class="border-slate-200 dark:border-slate-700">

<!-- CORRECT -->
<div class="bg-card">
<div class="bg-muted">
<div class="border-border">
```

### 4. Legacy Svelte reactive syntax for theme reads

```svelte
<!-- FORBIDDEN — Svelte 4 legacy syntax -->
<script>
  $: isDark = $themeStore.currentTheme === 'dark';
</script>

<!-- CORRECT — Svelte 5 runes -->
<script lang="ts">
  import { themeStore } from '$lib/stores/theme.svelte';
  let isDark = $derived(themeStore.isDark);
</script>
```

### 5. `.subscribe()` on the theme store

The runes-based `ThemeStore` class does not expose `.subscribe()`. Use `$effect` instead.

```svelte
<!-- FORBIDDEN -->
<script>
  themeStore.subscribe(val => { colorScheme = val.currentTheme === 'dark' ? 'dark' : 'light'; });
</script>

<!-- CORRECT -->
<script lang="ts">
  import { themeStore } from '$lib/stores/theme.svelte';
  let colorScheme = $derived(themeStore.isDark ? 'dark' : 'light');
</script>
```

## Adding a New shadcn Component

```bash
# 1. Add via CLI — this writes into internal/shadcn/ui/
npx shadcn-svelte@latest add <component-name>

# 2. Verify the generated file uses semantic tokens only
# 3. Do NOT hand-edit the generated file
# 4. If you need custom behavior, create a wrapper in components/ using bits-ui directly
```

## Adding a New App\* Wrapper

1. Create `src/lib/ui/components/AppMyComponent.svelte`
2. Use `bits-ui` headless primitives (verify the primitive exists in `package.json`)
3. Use scale tokens with explicit `dark:` variants
4. Export from `src/lib/ui/components/index.ts`
5. Import in consuming code: `import { AppMyComponent } from '$lib/ui/components'`
